* What Slice 1 delivers

- [[file:../sucoder/codex_state_runner.py][=sucoder/codex_state_runner.py=]] :: staged to the node like the native context installer and run as =python3 <runner> --scope <digest> -- <command>=; Python 3.6-clean because that is the default =python3= on some node images.
  It resolves =SUCODER_LOCAL_ROOT= at run time, creates =<root>/state/codex/<scope>/<run>/{db,home,snapshots}= with mode 0700, takes a per-scope startup lock, substitutes the =sqlite_home= placeholder with the absolute =db= path, binds local directories over =sessions=, =.tmp=, =tmp=, =thread-writer-locks=, =shell_snapshots= and =app-server-control= of the shared =CODEX_HOME= in a per-process =bwrap= namespace (plus a copy of =skills/= and file binds for =AGENTS.md=, =AGENTS.override.md= and =history.jsonl=), binding only entries that exist and recording the rest, launches Codex as a child in the same process group, ignores =SIGINT=, forwards =SIGTERM= and =SIGHUP= to bwrap's child, verifies placement through =/proc= (every =.sqlite= descriptor under =db=, every rollout descriptor on local disk), and exits with the child's code.
  Refusals exit 70 (=bwrap= missing, =CODEX_SQLITE_HOME= set, =sqlite_home= in the argv, =config.toml= or a =-p= profile, no =CODEX_HOME/sessions=, no local root); a misplaced store stops Codex and exits 71; =owner.json=, =status.json= and =runner.log= under the run directory record what happened.
- [[file:../sucoder/codex_state.py][=sucoder/codex_state.py=]] :: the scope digest (SHA-256 of gateway, remote user, resolved mirror path, slot), the placeholder inserted right after the executable, the outermost runner command, the staged source.
- =slurm.codex_state= :: =enabled=, =checkpoint_minutes=, =checkpoint_timeout_seconds=, =durable_root=; strict, requires =local_disk=; documented in =README.org= and =config.example.yaml=.
- Wiring :: =launch_agent= decides once per launch (=_codex_state_scope=), inserts the placeholder at the argv stage before nvm and installer wrapping, and wraps the staged runner outermost after the context installer; in remote-control modes the supervisor's server and client invocations both carry the placeholder.
- [[file:../tests/test_codex_state.py][Tests]] :: 34 cases: helpers, configuration, the wiring for TUI and remote-control commands, the runner on this node against a fake =codex= (placement, misplacement stop, early exit, SIGTERM through bwrap, every refusal) and against the real Codex app-server with the loopback fake model; the bwrap and Codex cases skip where those are absent.

* Next phase: Slice 2

Replication, generations and restore, per the revision section of the design:

1. A watcher in the runner follows each rollout under =home/sessions= by file growth and appends new bytes with =fsync= to =DURABLE/runs/<run>/rollouts/<thread-id>.jsonl=, recording offsets in =replica.json= and the replica age in =status.json=; never in Codex's path.
2. Database generations through the SQLite backup API, captured only after every replica is confirmed byte-identical to its local file; the manifest records each thread's =next_rollout_byte_offset= from =thread_history_projection_state= and the replica length.
3. Restore as generation plus replicas placed at the same relative paths and bound again, refusing any generation whose recorded offset exceeds the replica (the spike showed the projection then skips real turns and shows phantom ones); sealed means a backup taken after the owned server stopped.
4. Before an unattended =thread/resume=, refuse when =goals_1= holds an active goal or =queue_1= holds rows for the thread; =paused= is the hold for goals.
5. One startup line announcing that the managed history is fresh and separate from the shared one, as the design asks.
6. Timer checkpoint requests, =RemoteSession= metadata and renewal are Slice 3; do not start them in Slice 2.
