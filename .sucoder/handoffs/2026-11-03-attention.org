* The task: confirm Codex hooks from a live launch

The human's launcher defaults to Codex, and =attention.hooks: true= is set in =~ligon/.sucoder/config.yaml:249=, so the next SuCoder Codex launch on vantage is the first real one with hooks.
Codex hooks are untrusted until the account that runs Codex reviews them once; as of 2026-11-03 =~coder/.codex/config.toml= has no =session-flags= trust entries.
On the first hooked launch Codex shows "Hooks need review"; the human chooses "2. Trust all and continue".
Codex writes =[hooks.state."/<session-flags>/config.toml:<event>:0:0"]= entries; SuCoder never writes that file and never passes =--dangerously-bypass-hook-trust= (the human's rule: ask first).
The hook command is the same on every launch (the record key is in =SUCODER_ATTENTION_KEY=), so one review covers every later launch; this was checked in a throwaway =CODEX_HOME=.

What has been seen fire live: =SessionStart= (in the TUI it fires at the first prompt), =UserPromptSubmit=, =SessionEnd=.
What has not, and should be checked with =sucoder attention= (or =cat ~coder/.sucoder/attention/<mirror>--<target>.rec=) while the session runs:

1. =PermissionRequest= :: an approval prompt shows =waiting [permission]= and the watcher's push arrives (=permission= is in =notify_kinds=).
2. =Stop= :: a finished turn shows =idle=, then =waiting [idle]= "Codex is waiting for your input" a minute later; that is synthesized by =synthesize_idle_waits= (=sucoder/attention.py:452=), because Codex has no idle notification.  =idle= is not in the human's =notify_kinds=, so it lists but does not push.
3. =Interrupt= (Esc during a turn) :: back to =idle=.
4. =PreToolUse= with matcher =^request_user_input= :: a model question shows =waiting [question]=.

If any of these does not fire, the event names and matchers are in =CODEX_EVENTS= (=sucoder/attention.py:76=) and =codex_overrides= (=:209=); the launch wiring is =_with_attention_hooks= (=sucoder/mirror.py:5414=).
Record what was seen in =docs/attention.org:293= (open item 3) and remove the item once all four are confirmed.

Known gaps, documented, not bugs: MCP elicitations raise no hook; a failed Codex turn emits no =Stop= and reads =working=; a session launched with its own =hooks.*= override is left unhooked (=_codex_sets_hooks=, =sucoder/mirror.py:8139=).
