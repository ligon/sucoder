Prevent a reused managed run from advertising the previous launch's checkpoint count before its new checkpointer starts.
Keep acknowledged generations, unsynced-generation recovery, and transition history.

* 3. Definitions
=checkpoint.count= is the current Checkpointer instance's completed-capture count, not the run's durable generation sequence.
=last_generation= is acknowledged durable history; =unsynced_generation= is a pending acknowledgement that reuse must retain.
Readiness for the existing test client means a current-launch capture has completed, not merely that placement is verified.

* 4. Invariants
Reuse must retain the same stores, run identifier, immutable provenance, generation sequence, and transition history.
Do not change ownership, placement, shutdown sealing, capture deadlines, or unsynced-generation adoption.
A request made before scheduler startup must remain consumable after startup.

* 5. Reuse decisions
- Extend =Status.load='s existing transient-field removal to checkpoint.
- Reuse =_wait_idle='s count predicate; clarify why absent checkpoint means unready.
- Extend tests with preserved-history checks and a private gate on the second launch's Checkpointer.start.
The gate belongs only in the test wrapper; no production delay hook or new configuration is needed.
