* 3. Definitions in force

- Pool :: "Pools are explicit resources at a scope" (=llm-accounting/docs/schema-contract.md:79=).
- Utilization :: "a nonnegative decimal-string fraction consumed, not a percentage added across windows" (=schema-contract.md:187=).
- Consumption :: "Never sum all token fields or convert utilization changes to consumption" (=schema-contract.md:199=).
- Identity :: =row_identity= explicitly defines "Identity within an export; observation aliases are deliberately excluded" (=contracts.py:260=).
- Integration :: "Reports do not reserve quota or promise that concurrent/unrelated activity will fit" (=WORKPLAN.md:339=).
- Hours :: The conceptual design distinguishes collective draw per clock hour from resource use per agent-hour; residency, open turns and API waiting are different exposure measures.
- Model identity :: Requested, configured, native-reported and served identities are separate evidence; neither a launch label nor quota applicability proves the model that did work.
- Coverage :: Completeness of the instrumented population and coverage of the whole account are distinct; missing or external activity is unknown, not zero.
- Cost :: Native client estimates, provider-rated monetary observations, local API-reference conversions and subscription scarcity values are separate quantities.

* 4. Invariants

Keep observations, counter-derived flows, declared priors and forecasts distinct.
Preserve original collection/source times, unknowns, binding generations, applicability, quota-window kind and source quality.
Repeated collection of a snapshot is not another unit of consumption; interval revisions replace compatible source facts rather than adding to them.
Relevant account-binding or resource-semantic changes break comparability unless an explicit mapping establishes continuity; unrelated catalog additions do not.
Quota trajectory forecasting may use compatible utilization observations but cannot claim token consumption or attribute a shared-pool change to a particular model.
Normal sampling must not start inference, renew credentials, inspect another Unix identity or alter existing sessions.
Model-tagged throughput does not identify shared quota weights without variation and assumptions about background use, windows and workload.

* 5. Reuse decisions

Reuse accounting collection and validation rather than creating new provider quota clients.
Extend the existing repository/distribution under the proposed =llm_accounting.usage= namespace; install the usage command with the existing package and reuse shared schemas/configuration/CLI conventions where their contracts fit.
Reuse the existing public resource definitions and sanitized catalogs; add versioned history references around them.
Add a history store, publication events, attempt records and temporal joins because the current library is export-only and provides no observation database or cross-export history reconciliation.
Keep history envelopes and report contracts distinct within that repository; new storage must not change the existing accounting CLI defaults or published report semantics implicitly.
Add a prospective Claude request-metadata adapter as required new work for the model-aware pilot, after its identity, quantity and coverage semantics are verified; never use context-window occupancy as cumulative token use.
Add the required Codex telemetry adapter and supporting model-selection evidence; reuse shared ingestion/history mechanics while keeping source namespaces, account bindings and inclusion semantics distinct.
Extend the history envelope with model evidence, request/stream identities and coverage records because the accounting quota contract intentionally does not represent model-attributed use.
Keep the estimator separate from collection so later methods can replay the original evidence and price publications.

* 6. Design choices and verification

The practical design must choose storage, sampling, clock handling, deduplication, price publication, epoch boundaries and minimum export fields.
Remaining limitations are unknown provider denominators/replenishment rules, incomplete external activity attribution, and missing passive collection policy in the current combined Claude path.
These limit interpretation or specific live adapters; they do not block writing the design or collecting already normalized reports offline.
All 270 existing llm-accounting tests and its validator for three schemas/fourteen examples pass on the inspected baseline.
Four accounting reports in the original replay pass the same schema and binding checks.
Independent semantics and operations reviews accepted the final design after rechecking source-fact identity, knowledge snapshots, throttle fallback and descendant cleanup requirements.
The subsequent [[file:llm-usage-collection-review.org][model-identification red team]] finds that this acceptance did not establish readiness to estimate Fable-versus-Opus use: the first slice lacks a required model-observation stream.
The response revises that milestone, specifies the required metadata adapter and adds synthetic model-identification cases; native capture and calibration remain implementation work.
Both original model-identification reviewers accepted the revised specification after rechecking identity, coverage, hour semantics and emitter authentication.
That acceptance predates the explicit Codex scope extension; the implementation charter requires acceptance of both adapters rather than treating the earlier review as Codex verification.
Offline validation confirms the 14 scenario projections' referenced artifacts and numerical counterexamples; it does not validate an implemented reader or adapter.
Runnable artifact validation and review outcomes are recorded in [[file:llm-usage-collection.org][the collection design]].
The design reuses the definitions in sections 2-4; the history/capture mechanisms in section 5 are specified as new work, not represented as existing tested machinery.
