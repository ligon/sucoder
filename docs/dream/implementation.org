* Implemented slices: explicit evidence and native role publication

=sucoder dream plan= implements the first part of the [[file:../dream.org::#implementation][data-plane sequence]].
It freezes explicitly admitted local git selections or native Claude/Codex transcript prefixes and budgets in a private JSON manifest without inference, source synchronization, or repository writes.
Frozen-plan validation, private snapshots, deterministic quotation fixtures, native Org subtree checks, output-bound receipts, atomic candidate publication, and local run status are implemented.
Native Claude and Codex adapters now default to a source-grounded wiki author/editor with independent whole-candidate review; legacy =--mode notes= preserves the earlier extractor/verifier/grouping contract.
Wiki mode can revise existing topics while preserving their anchors and current editorial task subtrees.
Automatic receipt reuse in planning, general editorial validation and generic native adapters remain subsequent work.
Bounded deterministic wiki/source retrieval and fresh native readers are implemented; real-reader engineering acceptance is tracked in P3.
The planning manifest retains =execution.available: false= and =prior_wiki.progress: not_evaluated=: planning itself does not execute roles or establish accepted progress.
Original git-only frozen plans remain compatible, including their legacy execution-reason text.
No plan is evidence of an examined source, accepted claim, or integrated wiki generation.

Use an existing SuCoder configuration and a locally accessible configured mirror:

#+begin_example
sucoder --config ~/.sucoder/config.yaml dream plan SuCoder \
  --sources sources.json --base refs/heads/main
#+end_example

The required =--base= must exactly match the catalog's full =integration_ref= under =refs/heads/= or =refs/remotes/=.
Symbolic integration refs and =refs/heads/dream/*= are rejected.
The command never fetches; update the local integration ref through the normal workflow before planning if necessary.
Global execution-target, sudo, and interactive-launch flags are rejected.
Help works without a configuration file.

The source request format is a strict JSON object:

#+begin_example
{
  "schema_version": 1,
  "repository": "SuCoder",
  "integration_ref": "refs/heads/main",
  "units": [
    {
      "unit_id": "reply-semantics",
      "kind": "git",
      "shareable": true,
      "locator": {
        "repository": "SuCoder",
        "commit": "refs/heads/main",
        "path": "docs/reply-from-transcript.org",
        "lines": [93, 110]
      }
    }
  ]
}
#+end_example

The locator repository is another explicitly named configured mirror, or the target itself.
The commit may be a locally resolvable revision; the plan stores its full object ID.
Omit =lines= to select the entire file; otherwise it is an inclusive one-based LF line range, retaining original CRLF and UTF-8 bytes.
Only nonempty UTF-8 regular git blobs up to 16 MiB are inspected in this slice; directories, symlinks, gitlinks, binary NUL bytes, missing objects, traversal, and unknown fields are rejected.
A catalog is limited to 256 KiB, as are individual git tree listings.
=shareable= is mandatory and boolean: it records whether explanatory extracts may later be proposed for publication.
It does not grant permission to transmit private sources to a provider.

An optional =limits= object overrides positive integer defaults:

#+begin_example
"limits": {
  "max_units": 6,
  "max_source_bytes": 1048576,
  "chunk_bytes": 65536,
  "max_role_invocations": 40,
  "max_prior_bytes": 65536,
  "max_proposal_bytes": 131072,
  "max_consolidation_bytes": 229376,
  "max_elapsed_seconds": 900,
  "max_repairs": 1
}
#+end_example

At most one repair is permitted, and =max_repairs= may be zero.
Chunks cover every selected byte contiguously, preferring complete lines and preserving UTF-8 boundaries for long lines.
Each chunk reserves extraction and verification, plus one consolidation and the declared repair allowance.
New plans use =bounded-prior-v1=: index/settings plus an explicit topic or source-associated current topics and direct topic neighbors.
Without a relevant seed, the entire active wiki is selected when it fits; otherwise only orientation is delivered, with a bounded omitted-page catalog.
Selected Org pages include Talk and LOGBOOK content and count toward =max_prior_bytes=; necessary selected context must fit that allowance.
Omitted active pages retain exact frozen identities and byte ranges and cannot be overwritten as new pages.
Receipt associations select relevance only, including current human edits; they do not establish accepted progress.
Old frozen plans reconstruct their original all-active-pages policy without identity changes.
Consolidation planning checks that prior bytes and the proposal allowance leave space for briefs and metadata; exact staged-payload validation belongs to the later execution slice.
Planning itself has a separate 30-second inspection deadline and five-second git probe limits.

=--maintenance REASON --topic TOPIC= records an explicit maintenance intention and still requires nonempty sources.
Both options must be supplied together; this slice does not perform the maintenance.

Plans are stored in =<log_dir>/dream/<plan-id>/plan.json=, falling back to =~/.sucoder/logs/dream/= when =log_dir= is unset.
Runtime directories and plan files are created with modes 0700 and 0600, without changing the process umask or repairing existing directory permissions.
Storage inside any inspected repository is rejected.
The stored manifest is private: it contains absolute local mirror paths, frozen source/chunk digests, prior-wiki object identities, allowances, and coverage marked planned rather than examined.
Its SHA-256 identity excludes the identity field itself and the returned local plan pathname.
Existing identical private plans are reusable; a mismatching existing file is rejected.

An accepted =.sucoder/wiki/sources.json= registry must have integer =schema_version: 1= and a UUID-valued =repository_uuid=.
When absent, the plan proposes a new provisional UUID without writing a registry into the repository.
Separate initial plans may therefore propose different UUIDs; integration and later re-planning must establish the shared identity.
The planner does not yet discover shared receipts to skip extraction.

Exit 0 means a valid stored plan, 2 means invalid or unsupported input, and 3 means unavailable evidence/storage or an inspection allowance exhausted.
No installed launcher deployment follows from a source-tree change.
Run source-tree checks with =poetry run pytest -q tests/test_dream.py= from the mirror root.

* Frozen plans, snapshots, and deterministic candidates

The local data-plane commands use the stored plan pathname returned by =plan=:

#+begin_example
sucoder dream snapshot SuCoder --plan /PRIVATE/LOGS/dream/PLAN_ID/plan.json
sucoder dream run SuCoder --plan /PRIVATE/LOGS/dream/PLAN_ID/plan.json --harness fixture
sucoder dream status SuCoder --plan /PRIVATE/LOGS/dream/PLAN_ID/plan.json
#+end_example

All three commands print JSON and bypass interactive agent startup.
The installed launcher need not yet contain these source-tree commands; =poetry run sucoder= runs them from this checkout.
Native Org validation requires a locally available =emacs= executable with Org; no new configuration key or provider dependency is introduced.

=snapshot= verifies the plan's content-addressed identity and reconstructs its complete planning contract against current configuration, committed source objects, the designated integration ref, source registries, and prior wiki objects.
Only a still-provisional UUID is carried forward from the frozen proposal; a newly accepted or changed registry requires re-planning.
It then stores exact selected bytes and active prior-wiki bytes in private content-addressed files beside the plan, verifying digests before accepting them.
Stored paths must stay outside all inspected repositories.
Snapshot publication is atomic and retryable; an existing differing artifact is preserved and rejected.
Coverage is =snapshotted= with zero examined bytes: copying evidence does not establish extraction or comprehension.

=run --harness fixture= revalidates and snapshots first, then executes a deterministic quotation fixture over every planned chunk.
All selected units must be explicitly shareable; an external repository also needs an accepted UUID.
Private units may be snapshotted but cannot enter a fixture candidate.
The fixture accepts git evidence only.
Native =codex= and =claude= harnesses are described below; other harnesses fail without fallback.
The fixture records each delivered range and exact-byte comparison, retaining git commit, blob, selected lines, byte offsets, digest, and repository UUID in its receipt.
These checks prove delivery and literal-text preservation under a fixed rendering rule; they do not perform semantic extraction, model verification, synthesis, or a pilot evaluation.
Published quotations normalize CRLF to LF and use Org comma escapes to keep source headings and block terminators literal.
The exact original bytes remain in the private snapshot.

Fixture output adds a fresh topic page and receipt, initializes the target source registry only when absent, and appends a generation link to the existing index.
Existing pages, settings, archives, and human index content are preserved.
Native Org parsing checks generated targets and links within the changed files, without following setup files, evaluating Babel, exporting, loading user init files, or opening source links.
The receipt binds each quotation subtree and the generated index entry under =org-subtree-utf8-v1=: SHA-256 over UTF-8 bytes from the headline's native Org =:begin= through =:end=, including child content and trailing whitespace.
The fixture has a separate =git-quotation-fixture-v1= fidelity contract; its receipt must never suppress future semantic work.
General claim fidelity, TODO transition legality, archival moves, human-decision attribution, and links outside the generated set require later validators.

The coordinator assembles a tree from the frozen base through a private index and git plumbing, disabling hooks, external filters, signing, network transports, and inherited git redirection.
It leaves the invoking worktree, staged index, current branch, and integration ref untouched.
One ref transaction verifies the designated integration ref and creates =refs/heads/dream/<run-id>= only if absent; retry verifies an identical existing ref in the same transaction.
A changed integration ref or conflicting candidate requires re-planning.
Interrupted preparation may leave unreachable git objects; those objects do not establish progress.
The run record reports =candidate_ready= and =not_integrated= after publication.
The human reviews and integrates through the ordinary repository workflow.

=status --plan= checks the saved fixture against the current designated integration tree.
It reports candidate-ref availability separately from =not_integrated=, =integrated_fixture=, or =needs_reconciliation=.
It can recover a candidate published immediately before an interrupted local run-record write.
Integration validation requires the expected receipt and every required subtree binding; a retained receipt with an edited, missing, non-Org, or unlinked output requires reconciliation.
Squash integration is supported without requiring candidate ancestry.
This local status interface requires the saved plan and private snapshots; cross-machine receipt discovery and planning reuse remain unimplemented.

All fixture stages spend the declared elapsed allowance, and proposal/staged-output bytes are bounded before publication.
The role-invocation count represents deterministic fixture stages, with token and currency usage unknown; no native model is invoked.
Exit 0 means completed snapshot, prepared candidate, or completed status inspection; 2 rejects invalid/private/unsupported input, 3 reports unavailable evidence/storage, exhausted allowance or a ref conflict, and 1 reports failed fixture/Org validation.

A reviewer accepts or returns concrete blocking findings.
At most one editorial repair is allowed, followed by another whole-candidate review; a nonactionable revision request or persistent failure produces no candidate.
This repair is distinct from an uncertain native request, which is never silently repeated.
All calls, results and repairs use the shared invocation/time/proposal allowances.
Mechanical checks and model acceptance still do not prove semantic truth or future usefulness; ordinary review and reader acceptance remain required.

An author may decide that useful knowledge is already represented, or that no worthwhile edit is supported.
An unchanged proposal requires a reason and empty page/change/reference arrays; the independent reviewer still sees all selected evidence and prior pages and may reject that decision.
The one bounded repair can replace a mistaken no-op with a real source-grounded correction.
A checked no-op stores private coverage, rationale, review and native traces and returns =unchanged=, without a candidate or shared accepted-progress claim.

* Agent-independent dreaming

On 2026-11-08 the user requested that implementation prioritize Codex and generic agents alongside Claude.
The [[file:../dream.org::#pipeline][design's initial file-tool Claude adapter]] was a capability hypothesis; the implemented inline mode uses the same independent coordinator for both harnesses.
The planning implementation imports no native agent client, chooses no provider/model, and has no fallback harness.

Keep these interfaces separate:

- Evidence adapter :: Resolve and normalize immutable source selections, preserving native events, tool outcomes, lineage, unknown ranges, and exact provenance.
  Claude/Codex JSONL are input formats, independently of who performs a dream.
- Role adapter :: Execute a frozen extractor, verifier, or consolidator assignment for a specified harness and model.
  Every adapter must return the same versioned result contract: assignment/input identities, proposed artifacts, trace-supported delivered ranges, explicit unread/failed coverage, native usage, and capability limitations.
- Coordinator :: Own complete selected coverage, shared allowances, independent validation, source/output receipts, and atomic candidate publication.
  Native exit success and an agent's final summary cannot substitute for these checks.

Before either native adapter runs, feature-probe the installed version and verify its ability to restrict the input/output file view, expose usable traces, enforce deadlines/retries, and produce schema-bound role results.
A generic headless agent must satisfy the same contract through an explicit adapter; an arbitrary shell command returning prose does not establish those capabilities.
Unsupported capabilities fail before inference with no provider/model fallback.
Money or token limits are enforceable only when the adapter demonstrates run-wide accounting and enforcement; missing usage remains unknown.
This contract is exercised with deterministic role fixtures and isolated native executable fixtures, independently of live account availability.
