* Interpretation and limits

No cache read was reported by either native final aggregate, so this pair establishes no reuse of the unique synthetic prefix and no monetary or allowance saving.
It also provides no evidence of cached boilerplate reuse: both reported read counts were zero.
These are native-reported counters; the live provider wire was not intercepted, and the presence of underlying provider fields was not independently observed.
In particular, a native-reported zero write count is not proof that no backend cache entry was created.
No currency or actual subscription-credit charge was reported, and API list prices are not substituted for subscription usage.

The inference that a native thread ID also supplied its wire cache key comes from same-build offline captures; the live key itself was not directly captured.
Changing keys, backend cache policy, native counter exposure or another request property could explain the outcome.
This two-call result does not identify the cause, rule out subscription caching generally, or establish that API-key billing is required.
A cache miss in this pair is not sufficient grounds to relax isolation or the stable-profile certification gate.

The tool-omission method remains supported by the offline request evidence and removes 15,870 serialized declaration bytes in that fixture.
No production transport/profile/default was changed, no further real dream was launched to claim a caching benefit, and no memory generation was published.
The most informative further live control would keep a single isolated native thread across two synthetic turns, to distinguish fresh-thread behavior from absent cache telemetry.
That would be a separate diagnostic experiment and budget, not a silent change to production role isolation or an automatic third call here.
