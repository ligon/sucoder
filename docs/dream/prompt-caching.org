* Purpose and scope
:PROPERTIES:
:CUSTOM_ID: scope
:END:

Make repeated dream inputs eligible for provider prompt caching on both Claude Code and OpenAI Codex, while preserving source authority, native isolation and inference-free replay.
The [[file:../dream-prompt-caching-ledger.org][grounding ledger]] identifies the existing contracts at local main =dc62682=.
The [[file:runs/sucoder-e3.org][E3 experience dream]] spent 383,344 of its 482,186 input tokens on discovery and reported no cached input.
Discovery's first input was 12,854 tokens and its last 40,093 as observations accumulated.
These measurements motivate the change; they do not predict a cache hit rate or monetary saving.

The design has two capability levels.
The first release targets a stable trusted instruction prefix in both existing native transports, with accurate usage reporting.
Each native build must pass the request-capture certification below before that capability is advertised.
Caching frozen evidence and growing history requires a separate native block/message capability gate; the current one-prompt transport cannot claim that capability.
This distinction is part of the product contract, not an implementation detail hidden behind a generic "caching enabled" flag.
No direct provider API backend, retained native process, prewarming, extra paid request or live acceptance run is included in this design task.

* Provider facts and native evidence
:PROPERTIES:
:CUSTOM_ID: providers
:END:

The sources below were consulted on 2026-11-16; deployed build capabilities must be verified separately.

[[https://developers.openai.com/api/docs/guides/prompt-caching][OpenAI's caching guide]] requires a matching prefix and an eligible boundary.
For GPT-5.6 and later, the documented minimum is 1,024 visible tokens; implicit caching uses eligible message endings and explicit breakpoints are available in the Responses API.
Changing a relevant schema, tool definition, model or reasoning configuration can break reuse.
On these models a cache key is optional for accounting separation; supplying one does not manufacture a prefix match.
Cache reads and writes are included in the API's total input count, and writes have their own price.

[[https://platform.claude.com/docs/en/build-with-claude/prompt-caching][Anthropic's caching guide]] offers automatic or explicit =cache_control= boundaries, with model-dependent minimum lengths, up to four breakpoints and a bounded block lookback.
Its standard cache lifetime is five minutes, with an optional longer lifetime; generation time consumes that window.
Its API =input_tokens= excludes cache reads and writes, so total input is the sum of all three.
No fixed threshold, price, rate-limit treatment or retention lifetime is shared between the providers by assumption.

The [[https://platform.claude.com/cookbook/claude-agent-sdk-04-migrating-from-openai-agents-sdk][Claude Agent SDK cookbook]] documents automatic caching of native system prompts and tool schemas.
The [[https://code.claude.com/docs/en/cli-reference#system-prompt-flags][Claude CLI reference]] documents replacing the system prompt from inline text or a file and the associated loss of default instructions.
The installed =claude= is =2.1.323= and exposes that flag, stream-JSON input and existing restriction flags.
Help output does not prove that a supplied user content block or cache marker survives to the provider request.

The [[https://learn.chatgpt.com/docs/config-file/config-reference][Codex configuration reference]] documents =developer_instructions=.
Installed =codex-cli 0.167.1= accepts configuration overrides, but =exec= reads plain prompt text rather than a documented arbitrary provider-message array.
The existing app-server test harness offers a recording fake provider; it is a test pattern, not a compatible replacement dream transport.
Both native agents may inject hidden or runtime-specific context, so stable SuCoder bytes establish eligibility evidence only for the surfaces SuCoder actually controls.

* Common prompt plan
:PROPERTIES:
:CUSTOM_ID: prompt-plan
:END:

Introduce =dream-prompt-plan-v1= for new jobs, separate from canonical assignment serialization.
The logical plan has ordered segments, each with an ID, exact UTF-8 bytes, authority, source binding and digest:

| Segment | Contents | Authority | Reuse scope |
|---------+----------+-----------+-------------|
| policy | Role brief, interpretation rules and tool prohibition | trusted instructions | Same role/contract/build |
| static-data | Frozen project binding, purpose, memory leads, admitted prior support | untrusted data | Same job and role |
| observations | Existing discovery actions and observations, in recorded order | untrusted data | Same attempt; append only |
| current | Latest action allowances, budget advice, assignment/input IDs | current control envelope | One assignment |

Only coordinator-authored policy enters system/developer instruction surfaces.
Memory, retrieved passages, transcript text, model rationales, proposals and their embedded instructions stay at user/data priority even when unchanged.
Delimiters describe data; they do not authorize raising its message role.
The current control envelope carries only coordinator-authored fields and is authoritative over historical budget advice; the wallet remains the mechanical authority.
The model must still echo the exact current assignment ID, input digest and role.

Within one attempt, observation segment bytes are retained exactly and new segments are appended.
The complete semantic assignment remains available for identity, limits and recovery; it is not replaced with a lossy summary.
Current allowance advice and identifiers appear after reusable material in model-facing serialization.
They remain part of the canonical assignment and its hash.
The ordered plan also avoids duplicating a selected memory seed as a second full open-item body; references must resolve to the same frozen bytes, with no new retrieval or evidence admission.
Define an allowlisted, versioned field partition of the semantic assignment before writing a renderer.
Every field belongs to exactly one delivered surface or an explicitly named control-metadata slot; unknown, omitted and extra fields are errors.
Policy and native output schema are represented once, rather than copied again into user input.
The inverse projection must satisfy =canonical(reconstruct(plan, native_schema, control_metadata)) == canonical(A)= before request-envelope commitment and again during replay.
This includes the exact current advice, prior support, evidence bytes, qualifications, identifiers and role; a correct digest label alone is insufficient.
Deduplicated references are typed and content-bound, resolve uniquely inside the envelope, preserve order and authority, and cannot form cycles or select another memory item.
The native-schema and instruction-policy associations are checked against the frozen profile, so a field cannot move from data to instructions while preserving only its bytes.
Do not compact history, drop negative results or change source qualifications in this slice.
Existing delivery, consolidation and output byte limits continue to apply, including the full encoded prompt rather than only its new suffix.
Reaching a context/byte limit produces the existing bounded finish/checkpoint behavior, without an unbudgeted summarizer or native auto-compaction.

* Native profiles and capability gates
:PROPERTIES:
:CUSTOM_ID: profiles
:END:

Each new job freezes the requested layout, resolved profile and native executable build before semantic assignment.
Capabilities are fields, not one boolean: =instruction_prefix=, =user_block_boundaries=, =history_prefix=, =cache_read_usage= and =cache_write_usage=.
Each field records supported, unsupported or unverified, its source and the profile-test version.
Provider model, platform, reasoning settings, tool settings and native configuration affecting the request are part of the profile binding.
Freeze the schema-family policy and permitted variants in that profile; each assignment and delivery manifest separately binds the actual resolved output-schema digest.
A mandatory variant change starts a new cache frontier and may lose reuse; it never relaxes a finish-only restriction or mutates the frozen family policy.
Freeze the configured authentication route/mode, and record safely observable stable principal/workspace metadata where the native interface exposes it without secrets.
Before each fresh launch, compare only such documented observable identity metadata; an observed route/principal change stops before reservation, while a token refresh within the same observable principal is normal.
When identity is unavailable, record =account_continuity: unverified=; an opaque local cache scope never establishes continuous provider-account identity.
Do not persist/hash tokens or credential-file contents, and never automatically switch authentication or billing routes.

Certification distinguishes three observations: a stable application-controlled surface, a certified eligible provider prefix, and an observed live cache hit.
Both initial instruction profiles and later block profiles require two fresh recording fake-provider captures for each allowed policy/schema pair.
Change assignment IDs, advice and scratch paths between each pair's requests; verify the prefix bytes, authority, cache-affecting settings and an eligible write/lookup boundary remain reusable.
If the build cannot expose a recording test path while preserving the production request semantics, eligibility stays unverified and no =stable= profile is certified for that build.
Flag help, stable file bytes and a successful negative isolation test do not replace that request-level evidence.
An actual provider hit remains a separately authorized live observation; recording tests establish request construction rather than provider cache state.

** Initial profile: native-instructions-v1

Keep one fresh native process and private home per role invocation, the current Landlock boundary, authentication-only inheritance and strict tool/event rejection.
Keep the configured harness/model/authentication path; do not replace native subscription authentication with API billing.
For Codex, render the trusted role policy through a bounded =developer_instructions= override.
Its certified profile must name its launcher strategy explicitly.
This host's Node launcher uses =process.execve=, which closes descriptors other than stdin/stdout/stderr; passing a schema descriptor through that wrapper cannot work.
For the stable profile, resolve and pin the packaged vendor native executable before preparation, expose =launcher: direct-vendor-native= in status, and freeze the wrapper/package and native-build bindings.
Retain all existing command restrictions and reproduce only the verified wrapper transformations: unchanged CLI arguments, managed-package root and package-manager environment markers, and signal disposition.
Require recording tests of wrapper/direct-native request equivalence apart from the deliberate schema delivery path, plus authentication-route, environment, signal and descriptor tests for the pinned package/build.
If the wrapper/package format is unknown or equivalence fails, refuse the stable profile before reservation; no silent binary resolution, different package, API backend or writable-schema fallback is allowed.
Legacy jobs continue to use their original wrapper route.
For Claude, use inline =--system-prompt= text containing the trusted policy and every guard previously supplied by the default/native role instructions.
Replacement of Claude's default prompt requires a negative test for external tools, hooks, instruction injection and unexpected continuation before this profile can be enabled.
Do not include transcript or memory bodies in either instruction surface.
The initial profile delivers policy as argv text, not a file that the native process subsequently reopens.
Limit policy to 32 KiB of UTF-8 with no NUL; structurally encode Codex's configuration string and pass Claude's text as one subprocess argument, without a shell.
Bound the complete encoded argv plus environment to 64 KiB and below the observed platform launch limit with explicit overhead headroom; escaping expansion counts toward that bound.
If either bound fails, stop before reservation instead of switching to pathname delivery.
Only trusted policy enters argv; evidence, memory, credentials and prior support remain outside it.

Both profiles keep all assignment data in user input, in deterministic plan order with current advice last, under the lossless projection check above.
That user input may remain a single changing text block.
The declared capability is therefore =instruction_prefix= only; =history_prefix= remains unverified/unsupported until the next gate passes.
The initial prefix may fall below the provider/model minimum and yield no caching.
Do not pad it with irrelevant text or raise evidence authority to reach a threshold.
If the native agent prepends changing context before the policy, report that observed limitation rather than claim successful prefix caching.

** Additional profile: native-blocks-v1

The target plan places stable data and each immutable observation in native user/data messages or content blocks, with the current envelope last.
Use an eligible boundary after stable data and at an observation frontier.
Keep the instruction policy, provider settings and output schema stable within each role/phase; a required finish-only schema takes precedence over a cache hit.
Do not inject fabricated native assistant messages or replay hidden reasoning as observed facts.

This profile is released separately for each harness/build only after a recording fake-provider test demonstrates the actual request roles, bytes, ordering and cache boundaries through the native interface.
An installed flag accepting JSON does not satisfy the gate.
For OpenAI, the recording must establish eligible message endings or explicit breakpoints, not just a long common string.
For Claude, it must establish preserved user block boundaries, native cache-control placement, threshold handling and a frontier within the provider's lookback window.
At most three application breakpoints are planned, leaving room for a native-managed boundary; conflicting native ownership must be detected in the recording.
Use the native default short cache lifetime unless a separate explicit setting is reviewed; do not request longer retention opportunistically.

If the present native interface cannot express this plan without retaining hidden conversation state, record =history_prefix: unsupported= and retain instruction-prefix operation.
Supporting a persistent process or direct API would require its own isolation, recovery, authentication and budget design.
This document does not assert that either current CLI can already express full history caching.
The block-profile gate makes that uncertainty a release criterion rather than an implicit implementation assumption.

** Configuration and fallback

Propose =dream.prompt_layout: legacy | stable=, initially defaulting to =legacy= for rollout.
=stable= selects the strongest certified native profile for the explicitly selected build; status names its actual capability level.
If no certified profile exists, preparation fails before provider startup with an actionable diagnostic.
=legacy= uses the historical layout; it does not promise to disable any caching performed automatically by the provider.
There is no runtime downgrade, alternate model, account switch or paid retry after a request has started.
An ordinary cache miss or zero cached-token count is a successful uncached execution, subject to the same wallet.
When this setting is implemented, update the parser, CLI help, README and configuration example together.

* Identity, artifacts and replay
:PROPERTIES:
:CUSTOM_ID: replay
:END:

Leave =dream.canonical= and earlier assignment construction unchanged.
New jobs freeze =prompt_contract: dream-prompt-plan-v1= and a provider-profile digest in their header/execution descriptor; that descriptor participates in the run identity before an assignment is constructed.
After frozen budget advice creates the complete semantic assignment =A=, derive the prompt plan and exact native delivery manifest =M= from =A=.
=A= never contains =M='s digest, avoiding a recursive identity.

=M= contains the assignment digest, plan digest, exact inline policy and stdin hashes/byte counts, structured native argv/configuration, profile digest, actual schema digest, executable version and environment-policy digest.
Random scratch locations are execution plumbing: the manifest names logical slots, with a separate launch record binding each slot to its actual private launch object.
This does not claim to reconstruct hidden provider context; native wire-capture evidence and any unavailable provider-body hash are labelled separately.
Record =provider_request_sha256: null= unless the adapter actually observes that request.
Do not put raw credentials, authorization headers or credential-file hashes in either record.

One immutable private request envelope commits =A=, =M= and segment references before reservation.
Reserve against the combined envelope digest, then write the existing started marker and invoke the native transport with the verified envelope.
The transport reads envelope segments through regular-file/ownership checks into bounded parent-owned buffers, verifies the projection and hashes, and launches those exact argv/stdin bytes.
Use the existing owned unlinked input stream for stdin; replacing a journal pathname after that read cannot replace the launch bytes.
The initial profile has no native-reopened policy file and no pathname fallback.
Claude's schema is likewise passed as exact bounded argv bytes.
For Codex's required schema-file argument, stage the verified bytes in a Linux memfd and seal it against writes, growth, shrinkage and further seal changes before launch.
Pass the sealed descriptor directly to the certified vendor executable and use its =/proc/self/fd/N= path as the schema argument, binding the logical schema slot, bytes and descriptor identity in the launch record.
Retain the descriptor through complete child/process-group exit and reaping, never reuse its slot during a call, and close it on every exit path.
Do not grant general procfs access or add a rule for an anonymous memfd; verify inherited access under the unchanged Landlock boundary instead.
The alternative =/proc/<coordinator-pid>/fd/N= path is rejected: the current boundary denies access to the less-restricted parent's descriptor even though an unconfined wrapper probe can read it.
A recording test must establish that the native build accepts this path and reads the sealed bytes before provider work; otherwise the profile is uncertified and preparation refuses it.
There is no writable-path fallback, and instruction/schema replacement tests must attempt both pathname substitution and writes through inherited descriptors.
Local Node/Python-only probes verified the wrapper descriptor loss, parent-path denial and successful inherited self-descriptor access under Landlock; they did not run Codex against a provider or certify the native profile.
Private probe results are =/home/coder/.sucoder/logs/dream-cache-design/2026-11-16/=.
It records both =assignment_sha256= and =delivery_manifest_sha256= in the new trace contract, replacing neither with the other.
Result validation still checks the echoed semantic identifiers and native output schema.
Replay validates the complete envelope, launched segment bindings, native trace and result before using saved output.

Missing or changed envelopes after a reservation, assignment publication or started marker are corruption/unknown-outcome errors; never rebuild them under newer rendering code.
An incomplete envelope before any such publication can be rebuilt from its frozen inputs, with the commit point tested by fault injection.
Cache eviction, a restart or an expired provider cache only affects future request economics; it cannot invalidate an already completed local result or renew a job deadline.
An explicit new attempt gets new request identities and may run cold within the remaining wallet, following existing retry rules.
Earlier jobs take the exact old canonical-stdin path and retain their original briefs, traces, receipt usage and result identities.
No new cache metadata is backfilled into old receipt bytes.

* Isolation and independence
:PROPERTIES:
:CUSTOM_ID: isolation
:END:

Author, repair and reviewer use fresh native executions with explicitly constructed inputs.
The reviewer receives only the candidate and review inputs required by its existing contract, never an author's private native conversation.
Sharing identical policy-prefix computation does not grant access to another role's messages or substitute a prior judgment.
Cache namespaces, if a native profile exposes them, use opaque stable job/role/contract scope; they contain no private paths or raw memory.
They are accounting/optimization hints, not an access-control boundary or proof that provider caches are physically separate.
Provider caches remain under the selected account and provider policy; SuCoder does not create a cross-account cache service.
Prefix equality is never evidence that a source was admitted, reviewed or consumed.

* Usage and economics
:PROPERTIES:
:CUSTOM_ID: usage
:END:

Retain the untouched native usage object, its trace binding, and a separate versioned =dream-usage-v2= normalized observation.
Record =input_total=, =input_uncached=, =input_cache_read=, =input_cache_write=, =output=, provider-reported currency, field coverage and mapping provenance.
Unknown fields remain null; observed zero is a distinct value.
Support optional write breakdown by lifetime without adding that breakdown to its parent write total.
Every count is a nonnegative integer, excluding booleans; reject contradictory totals as invalid telemetry and retain raw values for inspection.
Invalid/missing telemetry cannot fabricate savings, hide an uncertain request or invalidate an otherwise completed structured role result.

| Verified native mapping | Total input | Uncached input |
|-------------------------+-------------+----------------|
| OpenAI-style inclusive total | native input total | total minus known read and write subsets |
| Anthropic-style exclusive input | uncached plus read plus write | native input value |
| Unverified native mapping | unknown | unknown |

Select the mapping by frozen native profile/event version, never by a harness name alone.
Do not assume missing writes are zero or add cache fields to an inclusive total.
Use one verified final aggregate per native invocation; CLI internal requests and per-message/iteration totals must not be summed again.
Partial totals are reported with known subtotals and a count of incomplete calls, rather than a misleading complete aggregate.
New budget status exposes normalized totals separately from the legacy raw-field aggregate; historical receipts remain unchanged.

Report cached reads divided by known total input only over calls with complete compatible fields, together with the excluded-call count.
Show input by role, cache reads/writes, native elapsed time and any reported currency.
When currency is absent, leave it unknown; a separately requested estimate must name its dated provider/model price schedule and authentication/billing assumptions.
Account for cache-write charges and expiry; neither cacheable bytes nor a high hit rate alone establishes net savings.
No hard dollar/token ceiling is added: current native adapters still cannot guarantee one.
All cold calls, misses, repairs and unknown outcomes count toward the existing call/time limits; no prewarming, probe or keepalive bypasses them.

* Implementation and acceptance slices
:PROPERTIES:
:CUSTOM_ID: gates
:END:

1. Usage and bindings :: Add versioned normalization and delivery manifests with fake transports only.
   Establish old-job replay with provider startup forbidden, including the real published E3 job.
2. Native instruction profiles :: Add deterministic trusted-policy rendering and mandatory paired fake-provider wire certification for every allowed policy/schema variant of each native harness/build.
   Retain =legacy= as the rollout default until the relevant native build passes its full negative/isolation suite.
3. Native data/history profiles :: Certify each harness independently against actual captured requests; if unsupported, keep the visible instruction-only capability and report the missing boundary mechanism.
   No release claim of full history caching is allowed on the strength of API documentation or CLI help alone.
4. Optional live acceptance :: A separately authorized synthetic two-request check per harness uses a useful fixed prefix above the selected model's threshold, one changed suffix, explicit model/authentication and a shared call/time ceiling.
   It records cache writes, reads, total input, elapsed time and currency availability.
   A miss retains diagnostics; it never triggers an automatic third request.
   A measured positive read establishes one live hit for that exact profile, not a general savings estimate.

Required deterministic cases include:

- Identical frozen policy bytes across changing IDs, budgets and scratch directories; data remains user-priority even when it contains forged system instructions.
- Exact canonical reconstruction of each assignment plus separately bound instruction/stdin/schema bytes; omissions, extra fields, stale advice, ambiguous/cyclic references and authority changes prevent launch or saved-result reuse.
- Truncation, symlinks, ownership changes and file replacement at launch; the native instruction text and schema cannot change after validation through a reopened writable pathname.
- Policy/argv/environment byte bounds, structural escaping including quotes/newlines/non-ASCII, and a native-visible request-capture comparison over changed scratch paths and current IDs.
- Codex launcher package/native pinning, wrapper-equivalent argv/environment/signals, sealed-descriptor survival, denial of the parent-proc workaround and unchanged native authentication/isolation restrictions.
- Safely observable route/principal changes stop before reservation; token refresh with unchanged principal remains valid, and unavailable identity remains explicitly unverified.
- Crash before/after envelope commit and reservation, missing manifests after started/finished calls, expired job replay and an explicit cold retry without duplicate provider work.
- Cold, warm, expired and evicted provider caches; actual cache state never changes semantic selection, call accounting or accepted evidence.
- OpenAI inclusive and Claude exclusive usage, nonzero writes, missing fields, observed zero, contradictory counts, duplicate final events and aggregate/per-iteration double counting.
- Provider/model/schema/effort changes; a finish-only schema remains enforced even when it invalidates a prefix.
- Reviewer canaries absent from author input and author-private canaries absent from reviewer input; no native session/home reuse across roles.
- Full-source receipt/admission and prior-support preservation regressions, both native protocol fixtures, and Python 3.9-compatible implementation.

Before implementation edits, run the project-required GitNexus upstream impact analysis on changed runtime symbols and report HIGH/CRITICAL risks.
Before a commit, run change detection; run targeted pytest and the appropriate broader project checks for the implemented slice.
The design review itself claimed neither runtime implementation nor a live cache test.

* Implemented interface and acceptance, 2026-11-16
:PROPERTIES:
:CUSTOM_ID: implemented
:END:

The human authorized implementation after review.
The default remains =legacy=; =dream.prompt_layout: stable= or exploratory =--prompt-layout stable= applies only to new jobs.
An explicit wiki writer selects it with =dream run MIRROR --plan PLAN --harness HARNESS --model MODEL --prompt-layout stable=; notes mode retains legacy delivery.
Resumed jobs use their frozen profile, not today's configuration.

#+begin_example
sucoder dream certify-cache --harness claude --model claude-sonnet-4-6
sucoder dream --harness claude --model claude-sonnet-4-6 --prompt-layout stable
#+end_example

The first command performs offline certification only; the second launches an ordinary budgeted dream and sends its admitted evidence to the selected provider.
Certification uses dummy authentication in fresh temporary homes, a local HTTP/WebSocket recording server and the production filesystem boundary plus a TCP restriction to the fixture port.
Default provider ports are denied, and real credentials, transcripts and wiki contents are never seeded.
The check allows at most 120 seconds and two native request invocations per production variant, currently 28 across 14 variants; native version probes are separate local subprocesses.
The 14 pairs cover project/experience discovery, with/without memory leads, regular/finish-only schemas, and author/repair/reviewer policies for editorial versions 1 and 2.
The fixture emits a schema-valid synthetic result for each actual output schema.
It records raw synthetic requests and usage, compares the complete eligible prefix and cache settings within each pair, and rejects external tools, unsupported cache modes, compression and exceeded byte/time bounds.
The private report is bounded to 8 MiB, with at most 4 MiB of captured request bodies.

Certificates live under =<log_dir>/dream-profiles/= and bind executable fingerprints, launcher, model, authentication route, frozen command template and the policy/schema catalog.
A successful report yields =state: certified=; =state: uncertified= is an inspected unsupported capability and creates no usable profile.
Inspect the returned JSON state even when the diagnostic command exits successfully.
Stable launch requires the matching successful report before creating a new exploratory job or reserving a native call.
Each assignment must match a certified policy/schema pair; unsupported variants fail without relaxing the schema or falling back to legacy.
Native upgrades, model/route changes and changed policy/schema catalogs require a new certificate for new jobs.
Raw credentials and credential-file digests never enter the certificate or job.
Before each launch, the transport validates safely observable identity from the actual staged credential copy as well as the original route, preventing a source-check/copy account-switch race.
Unavailable principal metadata remains explicitly unverified.

The installed Claude =2.1.323= passed all 28 fresh captures for =claude-sonnet-4-6= with synthetic native credentials.
Its supplied system policy arrived at an =ephemeral= cache boundary, before changing user data and scratch-path context.
Only the native structured-output tool was exposed.
Its usage mapping preserved uncached input, nonzero cache reads and writes, and one final aggregate.
The installed Codex =0.167.1= failed the first pair because the wire request still exposed additional tools despite the restriction flags.
Its captures also show a fresh thread-specific =prompt_cache_key=; no cross-invocation reuse is claimed.
The sealed schema descriptor reached the vendor-native executable, but that delivery observation does not override the failed capability gate.
Current Codex jobs can explicitly retain legacy delivery; stable delivery has no automatic fallback.
The subsequent [[file:codex-tool-omission.org][delegated tool-omission investigation]] found a sealed model-catalog configuration that omits all tools and removes changing skill-path instructions.
Its two fresh captures still differ in cache key, so that research does not enable a production stable Codex profile.
The subsequently authorized [[file:runs/codex-cache-c1.org][C1 live subscription pair]] returned correct structured results but zero reported cached-input tokens on both calls; it establishes no observed reuse and does not identify the cause.
The later ordinary [[file:runs/sucoder-e4.org][E4 experience dream]] reported 22,656 cached input tokens across three of fifteen calls through the same subscription route with legacy delivery.
This observes some subscription cache reuse, without identifying the cached segment, explaining C1's misses or certifying the stable Codex profile.
