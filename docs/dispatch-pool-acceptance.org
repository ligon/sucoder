#+title: PR 78: bounded pool acceptance on Savio
#+date: 2026-10-29

* Result and scope

The attach-only pool implementation passed a concurrent native trial with an
intentional worker interruption and a later replacement in the same allocation.
Native trial pin: =78f43ad1bceb1eb256a740d8f813a1fbd94184a0=.
The subsequent controller-only correction =23f74ae3a00ffaed2de223db7d7f48fd1f248b10=
preserves an already launched submission when its optional reservation-summary
update encounters a busy lock. Receiving helpers, workspace scripts, manifest
generation and CLI arguments are byte-identical between those pins. Its 40 pool
tests and Python 3.9/3.11/docs CI pass; the preceding full dispatch cohort passed
382 tests. GitNexus remains unavailable because its native library cannot load
libssl.so.3; manual caller and source comparisons are recorded in the ledger.

This accepts bounded pool lifecycle, synthetic scientific/API execution and
durable interrupted partial state. It does not establish credentialed full-country
or full-corpus scientific correctness, eight-worker capacity, automatic recovery,
or arbitrary-duration reliability. Allocation creation/requested-node convenience
remains outside the PR, and issue 77 remains open for broader follow-up.

* Native experiment

Fresh allocation =40631087= on =n0041.savio4= held four CPUs/32 GiB for at most
one hour. The explicit pool reserved two CPUs/16 GiB; each worker received one
CPU/8 GiB. Immutable source and the approved image were staged once in that
allocation. Each worker had a private checkout, HOME, native scope, runtime,
configuration/data/cache directories and actual local SQLite/WAL/SHM descriptors.

=tests/test_grain_collapse_cluster_features.py= and
=tests/test_gh871_most_complete_row.py=, with zero failures, errors or skips.
No survey data or reader credentials were supplied. Each created one private

* Durable verification

All three workers completed workspace and evidence publication. Separate
post-exit verification steps required exact scheduler terminal evidence and
absence of live members of the original worker cgroup before hashing native
payloads. For each worker, six database files matched the generation's full
SHA256/size records. Each recorded rollout prefix matched its authenticated
hash, with zero trailing bytes. No SQLite API or rollout deserialization was used.
Evidence inventory, file hashes, JUnit counts, source hashes, the single-document
commit, runtime identities and frozen receiving helpers were checked separately.

All workers reused the same image/source inode identities and asset-verification
receipt, while runtime roots and native identities were distinct. All pool
reservations were released from exact step/accounting proof. Both test allocations
were released after verification; coordinator allocation =40618485= remained running.

The deliberately interrupted native exited 143. The existing runner therefore
produced a =crash= generation, not a =sealed= one. Its retained partial state is
hash-verified, not a completed task or an unattended continuation authorization.
The runner's existing refusal of unattended crash-generation restoration remains
in force. Semantic resume of this partial conversation was not attempted.

* Original failures and corrections

Earlier allocation =40629482= is retained as a failed trial. One worker completed
the same tests and 660 cycles and sealed native state, but its final workspace
publication exceeded 30 seconds. A diagnostic run in the stopped private checkout
measured one Git push at 31.92 seconds. The other worker stopped at the harness's
30-second documentation-commit deadline. Neither original result was relabelled,
retried or resumed. A follow-on request was refused before reservation/launch
because that allocation no longer had enough lifetime; its empty reservation
record is preserved.

The new =--publication-timeout= gives each Git/WIP publication a bounded budget
(default 30, maximum 300 seconds) and expands the shutdown window accordingly.
The accepted trial used 120 seconds. The harness separately allowed 120 seconds
for its documentation commit. Managed-state/cleanup timeouts and inspection
policy were not weakened. A late reservation-summary lock conflict in the accepted
trial was reconciled through the already durable receipt, without duplicate
submission; the subsequent controller correction makes that successful launch
explicit in the CLI result.

Earlier country-worker inspection failures recorded in the PR and ledger remain
historical failures. This acceptance does not retroactively establish their
scientific output, native preservation, or exit-interval duration.
