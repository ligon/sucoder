* 1. Task

Prevent mechanical identifier copying failures such as [[file:dream/runs/sucoder-e4.org][E4]] by scripting native reply submission.
The baseline is local main =ea73e10=.
New default dream jobs use a versioned body-only native reply; Python attaches the frozen assignment ID, input checksum and role.
Existing job headers, specifications, assignments and traces retain their original interpretation.
No paid retry or reinterpretation of E4 is part of this implementation.

* 3. Definitions

A semantic assignment remains the canonical task used by the wallet, evidence checks and saved result identity.
A submission contract specifies the model-facing reply schema and deterministic metadata attachment.
A body-only reply contains substantive fields, including failures; it contains no assignment ID, input checksum or role field.
The coordinator's transport supplies those three fields from its frozen task, never from model text.
Raw native stdout remains unchanged and is re-parsed during replay.
Native usage and native completion remain distinct from an accepted semantic result.

* 4. Invariants

Keep native isolation, tool prohibition, byte/time/call limits, independent review and compare-and-swap publication.
Keep raw trace/result/wallet/assignment bindings; a changed body, a mismatched submission manifest or injected metadata must be rejected.
Persist the new contract in new job headers and editorial specifications and include it in assignment/run identity before reservation.
Old traces without that contract still require the model's exact echoed identifiers; E4 stays incomplete.
No failure authorizes an automatic paid retry, manual hash correction or memory publication.
Per-assignment enum values would make schemas volatile, so use a stable body schema and retain exact certificate coverage.
Earlier cached profiles remain replayable; new profiles must certify the new body policy/schema pairs.

* 5. Reuse decisions

- Reuse :: Coordinator invocation, persistent wallet, artifact store, native trace parser, full semantic result validation and publication.
- Extend :: A shared submission projection/manifest/parser wraps body-only native output with coordinator-owned metadata.
  No such wrapper exists; current schemas require model-generated identifiers.
- Extend :: New default project/experience job headers and their editorial specifications freeze the new contract; explicit historical notes/reader contracts remain compatible.
- Extend :: Lossless stable prompt envelopes and the fourteen-case certifier cover the body-only schema and trusted policy without weakening certificate matching.
- Defer :: Stateful agents, coordinator tools accessible to models, direct APIs and automatic retries; none is needed to remove metadata copying.
