* Finding
The three normal-priority failure snapshots in [[https://github.com/ligon/sucoder/issues/79#issuecomment-6508794033][issue 79]] show kernel exit in progress: stable owned UID/starttime, flags =0x400004=, state I, and vanished exe/cwd/root links.
The flags include PF_EXITING, not PF_KTHREAD; I alone does not classify a process as a kernel worker.
Linux tears down resources before its terminal process state is observable, so an immediate Z/X check can refuse a process in that interval.
This explains the inspection failure mechanism; it does not establish how long the historical interval lasted or whether scheduler activity affected its duration.
See the [[file:dispatch-exit-proof-ledger.org][ledger]] for primary kernel sources, ownership definitions, measured probes, and invariants.

These limits bound deliberate polling, not every kernel/proc read.
The one-second ceiling is a conservative finite trial, not a measured upper bound on arbitrary kernel exit cleanup.
Persistent unreadability or a longer exit interval still refuses.
