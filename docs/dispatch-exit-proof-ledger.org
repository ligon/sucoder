Prevent a short-lived owned tool process's kernel exit cleanup from aborting an otherwise correctly placed dispatcher.
Require fresh terminal proof before excluding an unreadable process; keep local SQLite verification, ownership, and preservation rules intact.

* 3. Definitions and evidence
PID alone is not process identity: require the ownership scan's UID and starttime, with fresh observations before accepting a terminal state.
State I means TASK_IDLE, not a kernel-worker classification.
Linux v4.18 defines PF_EXITING as 0x4 and PF_RANDOMIZE as 0x400000 in [[https://github.com/torvalds/linux/blob/v4.18/include/linux/sched.h][sched.h]].
The three normal-QOS issue-79 receipts have flags 4194308 = 0x400004, matching before/after starttime and ownership, state I, and ENOENT for exe/cwd/root.
These flags establish exit-in-progress, not completed cleanup or safe preservation.
[[https://github.com/torvalds/linux/blob/v4.18/kernel/exit.c][do_exit]] sets PF_EXITING before exit_mm, exit_files, exit_fs, and exit_task_namespaces; exit_notify follows later.
[[https://github.com/torvalds/linux/blob/v4.18/fs/proc_namespace.c][mounts_open_common]] can return EINVAL after nsproxy is removed.
The node runs vendor kernel 4.18.0-553.150.1.el8_10; upstream ordering explains the observed error family but is not a claim to have audited every vendor patch.

A bounded own-process probe on n0232 observed 23 FD/mount errors across 200 ordinary Git exits; nonterminal observations included PF_EXITING with state R, followed by the same PID/starttime reaching Z within 6.3 ms from launch.
The first namespace probe failed its shell redirection because /dev was not device-bound; its receipts are retained as a setup failure, not Git acceptance.
The corrected namespace probe device-bound /dev and ran 100 Git exits; all had an exiting-state metadata error, with state D or R and at most 22.3 ms from the first such error to terminal/gone proof.
Neither local probe reproduced the historical state I interval or established its maximum duration.
Raw metadata and diagnostic scripts, including the failed-redirection probe, were copied to =/global/scratch/fsa/fc_jevons/ligon/burst/sucoder-issue79-20261029-5cJvtj=.
No environment, FD-target, database, transcript, or survey contents are inspected by these probes.

* 4. Invariants
PF_EXITING, I, EACCES, EPERM, and EINVAL never independently authorize skipping a PID.
Only fresh same-incarnation Z/X or a proven gone proc directory permits exclusion after metadata failure.
Any observed UID/starttime change refuses immediately; later disappearance cannot erase that evidence.
Unknown original identity, malformed metadata, or persistent live unreadability still refuses.
Every actual misplaced descriptor remains a failure; no inspection retry erases a placement observation.
Use a shared finite deadline and finite poll count, not an additional full allowance for each PID.
Do not change final sealing, checkpoint deadlines, cleanup ownership, or native-state success classification.

* 5. Reuse decisions
- Reuse PR 78's identity and terminal-proof helpers, its inspect_placement integration, and terminal-grace regressions independently of pool code.
- Extend identity metadata with kernel flags and allow a bounded longer terminal-proof wait only for an observed same-incarnation PF_EXITING process.
- Keep the short generic grace for other metadata races; both paths require the same terminal proof.
- Retain bounded diagnostic records and aggregate counts in placement results, with the failure context preserved on refusal.
- New deterministic cases cover delayed I/PF_EXITING -> Z, persistent exiting state, PID/UID reuse, malformed/raced flags, shared budget exhaustion, and continued misplaced-store refusal.

* 6. Open questions and acceptance
The exact duration of the three historical I-state intervals was not captured; do not present a proposed wait bound as a measured maximum.
Independent review must assess the wait policy and identity binding before native acceptance.
That review found and reproduced a PR 78 mismatch-loss race: different first/last starttimes could become unknown and later pass on disappearance.
The correction checks first starttime, UID, and last starttime as each is observed and preserves any mismatch as an immediate refusal.
Independent review approved the corrected source for the bounded pilot: 73 focused tests passed, and a real nondumpable same-UID child remained refused without extended grace.
All 304 dispatch tests passed in Slurm job 40621363 at source 58c06dc.
Two new integration regressions fail on main; five delayed-exit/mismatch regressions fail on PR 78 and pass here.
The chosen ceiling is one second from the first metadata error per inspection pass; unflagged/unknown processes retain the shared 50 ms bound.
Only deliberate polling is bounded; these deadlines are not a guarantee on arbitrary kernel proc reads.
Successful race diagnostics retain the latest 16 records and an aggregate count; refusal context is retained before cleanup.
Run a finite same-profile concurrent separate-allocation pilot through final checkpoint/publication, preserving failed receipts and distinguishing task, native, supervisor, and preservation outcomes.
Do not deploy to an installed CLI or replace peer workers as part of this branch.

The two-worker native pilot completed on distinct nodes with 76.45 seconds of overlapping source churn.
Both workers exited zero, observed local SQLite, sealed final state, and published unchanged source and verified evidence.
Four EACCES metadata races reached fresh terminal proof; two observed PF_EXITING in R/D before disappearance.
All four recovered within 15.78 ms, so the extra allowance beyond 50 ms and the historical I interval remain demonstrated only by deterministic regressions, not these native receipts.
