* 3. Definitions in force

A live allocation or tmux pane does not prove a live agent.
Unknown discovery is not absence; exit 3 already denotes unavailable inspection in =cli.py=.
The shared mirror is durable storage; the active working clone may be node-local and temporary.
The relay runs with its own account's home/config and does not let callers supply arbitrary configuration or --force.
Existing managed state identifies histories with scope/run identity rather than job ID alone; the new snapshot keys do not replace that identity.

* 4. Invariants

Do not allocate, cancel, authenticate interactively, repair records, restore generations, or write repository content while observing.
Do not widen existing privileged relay executable/configuration authority.
Do not replace canonical managed-state ownership, recovery, renewal, or snapshot logic.
Keep current context local even if discovery is relayed.
Carry source provenance before joins; do not merge equal numeric job IDs from different clusters/accounts.
Keep base Python 3.9 compatibility and existing CLI behavior unless a reviewed change explicitly says otherwise.

* 5. Reuse decisions

- Reuse :: Pure path helpers, parsers, configuration resolution rules, replacement-holder rules, and catalog rendering.
- Extend :: Observation collection with bounded noninteractive policy, source provenance, typed errors and diagnostic record reads; relay capabilities/JSON; CLI commands.
- New :: Public schema and serialization boundary, because rendered tables/internal dataclasses do not provide a stable contract.
- New :: Workspace binding consistency guard, because no generic cross-harness binding currently exists; reuse the final-cwd launch boundary.
- Conditional new :: Thin companion MCP package on Python >=3.10; no server until P3 is approved.

* P1 implementation choices (2026-10-22)

The human approved P1/P2 after both P0 reviewers cleared the contract.
The shared CLI callback is bypassed only for structured observation and relevant help requests, avoiding startup privilege checks.
The human sessions renderer and mutation consumers retain their existing paths.
The JSON adapter supervises a bounded worker so configuration reads and YAML decoding cannot escape the command's subprocess deadline.
The worker's probes remain in its owned process group; the supervisor reaps/terminates that group, while a privileged relay runs its own supervisor and deadline.
No process signal targets an existing SSH master, tmux server, agent or allocation.

Pure parsers, replacement-holder semantics, local-tier work_path and confined_tmux_target are reused.
Transport is deliberately separate from interactive capture/reconnect helpers.
Sources with unknown accounts or endpoint-affecting options are conservatively separated; legacy sockets without verifiable account/endpoint identity are not reused for overridden routes.
Scheduler panes are batched through srun and login pane enumeration is fused; probes are sequential, within the maximum-four concurrency contract.
This trades peak throughput for simple deadline and ownership semantics.

GitNexus impact was attempted but its native library could not load libssl.so.3 in this environment.
Source/caller review identified main, sessions and relay_sessions as the only modified existing functions, plus the Typer app construction; new functionality lives in separate observation modules.
Existing human discovery/messaging tests passed after those changes.
No infrastructure repair or index regeneration was attempted.
