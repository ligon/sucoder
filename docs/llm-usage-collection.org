#+TITLE: Practical Design for LLM Usage Collection
#+AUTHOR: Sue
#+DATE: 2026-10-17
#+DESCRIPTION: A passive history of quota trajectories, advertised prices and supply state for estimating depletion rates.
#+PROPERTY: header-args :eval never-export :tangle no :exports code

* Deliverable and first useful result

Build =llm-usage= as a small local collector and history reader around =llm-accounting=.
Its first result is a time series for every observed quota constraint, linked to the advertised price vector and supply state that were in force.
That series supports comparisons of reset-adjusted depletion pressure without completed-task labels, transcript ingestion or a demand estimator.
Native activity and usage counters add evidence for hourly API replacement costs and model attribution when a source supports them.

This is a design proposal, grounded in the [[file:llm-usage-collection-ledger.org][prior-art ledger]].
The economic objective and meaning of an agent-hour are in [[file:llm-shadow-values.org][Standing Shadow Values]].
No collector, native hook or timer has been installed by this design work.

There are two implementation slices.
Slice A collects normalized accounting snapshots, immutable price/supply publications and attempt records, then exports the quota series and its price history.
Slice B adds optional native counters, lifecycle observations and decision-price references.
Slice A is independently useful; a per-model token rate is unavailable until Slice B has sufficient evidence.

* Ownership and interfaces

=llm-accounting= continues to own provider requests, account binding, credential access, quota semantics and sanitized reports.
=llm-usage= owns sampling, durable history, historical publication versions and temporal joins.
The rate estimator consumes exports and writes separately versioned estimates; it does not rewrite collected observations.
SuCoder will emit small optional lifecycle and decision records instead of becoming another provider client.

Use Python 3.11, matching the current accounting package.
Keep the first implementation in an =llm-usage= package rather than coupling its storage to SuCoder's session files.
The following are proposed interfaces, not existing commands:

- =llm-usage init= :: Create an owner-private dataset and record the route/source registry from an explicitly selected user configuration.
- =llm-usage sample= :: Attempt one bounded collection of the configured accounting targets and commit one immutable batch, including partial or failed results.
- =llm-usage ingest-report PATH= :: Validate and store an existing accounting report with its original times and source mode; do not relabel it as a new live reading.
- =llm-usage publish-prices PATH= :: Validate a complete route price vector, commit a publication event and return its immutable ID.
- =llm-usage publish-supply PATH= :: Record commercial terms, API tariffs, availability and declared rate assumptions separately from advertised shadow prices.
- =llm-usage record= :: Accept a bounded, allowlisted native metadata or decision event through stdin; never accept arbitrary executable adapters from data.
- =llm-usage export --view quota-series|usage-intervals|price-history= :: Read committed history offline and emit JSON Lines with explicit evidence and coverage.
- =llm-usage status= :: Show last attempts, source age, cooldowns, missing price/supply publications and unobserved activity sources.

Configuration lives at =~/.config/llm-usage/config.json=, with the usual absolute =XDG_CONFIG_HOME= override and an explicit =--config= option.
It names the dataset, state/runtime directories, existing accounting configuration path, selected targets, publication authority and sampling policy.
Reference the accounting configuration rather than copying its profiles, expected private account IDs or credentials into the history.
There is no current-directory configuration discovery.

* Slice A sources and cadence

** Accounting snapshots

Use the library's =collect_live= entrypoint, followed by its =validate(report, "report")=, =check_binding= and public-field checks.
Pin the compatible accounting contract and implementation version; record both in the sampling policy.
Store each complete sanitized source-group report as an artifact once per batch, preserving catalogs, target results, observation times, windows, verification and exclusions.
Do not reduce it to percentages alone.

Select all relevant subscription constraints in one invocation, reusing the accounting library's source coalescing for overlapping target selections.
Configure one polling owner per provider reporting identity and pool, independent of the number of models, SuCoder mirrors or remote sessions that draw on it.
Account-wide quota observations already include external activity to the extent the provider reports it; adding native token use to a quota percentage would double count unlike measures.

There is a required fix before routine Claude polling.
At accounting commit =ed7c851=, =check_native_context= requires =native_state_policy=forbid_changes=, but the combined collector calls =read_claude_credential=, which can invoke a minimal inference turn on expiry.
Restore that existing policy by using the stored-only credential reader in the combined passive collection path and testing expired credentials without subprocess launch or auth-file change.
The direct interactive probe's renewal behavior is a separate interface.
Until this is fixed and version-gated, refuse both manual and scheduled live Claude samples with =passive_policy_unavailable=; saved-report ingestion remains usable.
Do not work around this by monkeypatching a reader, checking expiry in a racy preflight or copying credentials.

** Sampling policy

Start with a five-minute subscription cadence, configurable per source, plus an explicit manual sample operation.
This yields 288 nominal samples per day per polling owner.
Use a fixed cadence independent of advertised price or observed activity; record deviations so quiet periods are not selectively missing.
Do not add adaptive high-frequency polling to the first slice.

Allow one in-flight sample per polling owner under a lock on a local runtime filesystem.
Start an attempt on the next scheduled tick, with a proposed 120-second dispatch budget and the accounting library's smaller per-source budgets retained.
Invoke =collect_live= with eligible targets grouped by coalescible source identity; stop starting source groups when the dispatch budget is exhausted and mark the remaining groups skipped.
Each group produces its own accounting report artifact and result event within the batch.
Let an in-flight bounded source finish its cleanup before releasing the owner lock; the dispatch budget is not a promise that every process exits at exactly 120 seconds.
Graceful cancellation must reach the accounting/native collector's cleanup path and reap its children before that lock is released.
For timer-enforced hard deadlines, require a service scope that contains all descendants, including independently created process sessions, and kills/reaps the entire scope before another attempt can run.
A systemd user service with control-group cleanup is the proposed Linux mechanism; killing only an outer worker/process group is insufficient.
If that containment is unavailable, use the dispatch budget and native per-source bounds, report that a hard deadline is unsupported, and do not advertise a kill-and-cleanup guarantee.
If the previous attempt is still running, skip the tick and record =busy= rather than queueing catch-up requests.
Record missed ticks after restart as a gap; do not backfill them with later values.

Persist provider =retry_not_before= values across invocations and honor them before another request.
Throttling without a usable Retry-After and other transport failures use a recorded 5-, 10-, 20-, 40-, then 60-minute backoff, reset by success.
Key scheduler state by the configured reporting identity/coalescible source, not by individual metric or model; it can be rebuilt from accepted attempt records and their policy version after restart.
Filter cooled-down groups before invoking =collect_live=, whose current cooldown dictionary is invocation-local; emit skipped attempt events for those groups while other eligible groups proceed.
An expired or rejected credential remains an explicit failure without login or renewal; check again on the ordinary cadence or after a manual request.
Every skipped attempt says why it was skipped.
This provides a recorded observation schedule, including gaps and failures, rather than an apparently regular series containing invented values.

An external user timer invokes =sample= on the owning host; the package need not contain a daemon.
A timer example is an implementation artifact to supply with Slice A, and enabling it is a separate operational action.
Do not start a job on every compute node to poll the same account.
API reporting targets, where configured, get a separately declared cadence appropriate to their report grain; daily cost buckets are not five-minute resource-flow observations.

** Advertised prices and supply

Price publications contain the whole route vector, including unavailable quotes, currency, hourly convention, method version and declared assumptions.
Assign a dataset-scoped publication ID and publisher capture time; retain a parent publication ID to establish the authorized publication sequence.
One configured authority publishes a given price series; branches or conflicting successors remain conflicts rather than being resolved by import order.
Manual prices are valid first inputs and are labeled =declared=.

Keep supply publications separate.
They contain route/access mappings, usable alternatives, native-unit marginal tariffs, known included-use constraints, effective terms and verification/as-of dates.
Hourly API replacement rates are declared or estimated conversions of tariffs, not provider-reported bills.
Unknown tariffs, model availability or API permission remain unknown even if a reference price has been entered.

The publication tool records the versions it actually publishes, with a capture-time uncertainty bound; it does not accept an arbitrary historical effective time for a newly advertised price.
An imported publication may retain a verified original effective time; otherwise its first local observation is the earliest established time.
If a separate price producer writes only a latest-value file, polling that file cannot recover intermediate quotes.
Require it to publish history through this interface, or mark the unobserved price history incomplete.

Price history establishes what was advertised, not what the human saw.
An optional =quote_read= or SuCoder =decision= event references the exact publication used, including a stale publication if that was the actual input.
Sampling must not silently replace an older decision quote with the most recent advertised vector.

* Records and identity

Use a provisional =0.1-design= envelope until the implementation contract is reviewed.
The committed batch contains =format_version=, =data_mode=, =dataset_id=, =batch_id=, =producer_id=, =recorded_at=, an =events= array and an =artifacts= map.
Modes =live= and =synthetic= occupy separate datasets.
Each event has an opaque dataset-scoped =event_id=, =kind=, =captured_at=, =source_ref=, nullable =price_ref=, =supply_ref= and =binding_ref=, plus a kind-specific =payload=.
IDs identify records; their spelling carries no metric meaning.
Artifacts are addressed by SHA-256 of their canonical validated JSON value, using sorted keys, compact separators and ASCII escapes; monetary and fraction values remain decimal strings.

The event families are:

- =registry_publication= :: Versioned public route, source and resource mappings; model/harness, commercial access, shared constraints, quality/family labels if declared, and binding/semantic fingerprints.
- =accounting_sample= :: Attempt start/finish times, selected targets, collection policy/version, control status and the accounting report artifact reference when one exists.
- =attempt= :: A skipped or failed attempt with controlled reason, nominal tick, start/finish and retry time; no fabricated report or observation.
- =price_publication= :: Complete advertised vector, parent publication, authority, method/assumption versions and publication-time uncertainty.
- =supply_publication= :: Commercial terms and tariffs, route availability, source/as-of information and declared hourly conversion assumptions.
- =counter_sample= :: Native counter identity and epoch, source measurement/capture times, unit/category, value, declared =cumulative_flow=, =interval_flow= or =snapshot= semantics, scope and inclusion relationships.
- =activity_event= :: An observed session/turn lifecycle, model change or liveness state, with a named time basis and opaque source identity.
- =decision= :: Contemplated/selected route, exact price and supply publications used, decision time and controlled outcome; task text and reasoning transcripts are excluded.

The [[file:examples/llm-usage-collection-v1.json][synthetic replay]] illustrates the envelope, publications, accounting reports, a counter interval crossing a price change, a failed sample and a reset boundary.
It is a design fixture, not an adopted public JSON Schema or a live account capture.

** Resource keys

Keep each accounting report's =identity_namespace= and public catalog with its =binding_ref=.
A binding publication is a sanitized projection of the validated provider/access/pool/scope/metric catalogs and their generations, not a hash or copy of private credential configuration.
Persist the metric ID and full typed definition, scope ancestry and generations, pool definition, related access constraints and applicability.
Changing account binding, namespace, physical pool or metric semantics creates a new comparable-series key unless an explicit reviewed continuity mapping establishes equivalence.
An unrelated catalog addition or a new registry publication alone does not break a trajectory whose relevant resource fingerprint is unchanged.

An observation reference such as =o001= is local to its report.
The historical reference is the report artifact plus local alias; it never indexes a global row by alias alone.
Within a binding, the trajectory key excludes source observation time and changing reset timestamps, while retaining the stable physical constraint selector and observation scope/dimensions.
The complete reported window remains on every point and determines episode boundaries below.
This permits a series across observed resets without treating different constraints as one resource.

Repeated unchanged quota values at later genuine collection times are useful observations and remain in the trajectory.
Define a separate candidate quota source-fact key from the bound physical constraint, full normalized original window, source authority/compatible version, data mode, and original =observed_at= and =collected_at=.
Exclude the measured value from that key so differing values cannot evade conflict detection by becoming different facts.
Resolve report-local pool/scope references through the binding before using the accounting physical-row identity rules, and normalize equivalent UTC timestamp spellings.
For a matching key, compare normalized measurement equality and original source/binding/coverage evidence separately; incompatible values or evidence remain conflicts rather than an arbitrary selected point.
Export =generated_at=, reassessed freshness and local aliases are assessment evidence, not additions to the source-fact key.
Retain their report references even when the quota-series view coalesces equal source facts.
Where the available fields cannot distinguish a re-export from a fresh same-time reading, preserve that ambiguity instead of claiming exact source identity.
Every locally accepted batch has a mandatory receiving-dataset receipt containing its content hash, local acceptance time and original producer/batch identity.
Re-ingesting the same artifact or source event creates another receipt at most, not another reading or quantity.
Import keeps original dataset, producer, event IDs and source times.
The same event ID with different payload is a conflict; identical imports are idempotent.
The receiving dataset's receipt is separate from the original batch's =recorded_at=; a late import was not known locally merely because its source timestamp is old.

For interval flows and cumulative counters, keep source-native scope and revision identity separately from local capture identity.
A provider period report has its original grain and dimensions; a later explicitly identified revision supersedes the compatible previous fact in derived views while both records remain auditable.
Overlapping periods, parent/child totals and mirrored sources are not summed.
Where sources lack a reliable revision or request identity, mark the ambiguity rather than asserting exact deduplication or attribution.

* Time, boundaries and joins

Store UTC instants as reported, the collection start/finish bracket, the producer's clock-uncertainty bound if known, and a monotonic duration with boot/process epoch for local attempts.
Source =observed_at=null= remains null; =collected_at= is not relabeled as a provider activity timestamp.
Source capture time and later import time remain separate.
Record clock reversals and uncertain cross-host order explicitly.

Price and supply joins use the publications effective at the observation or decision time, never a future publication or import completion order.
An accounting sample's =price_ref= says which vector the sampler observed; it does not attribute all earlier resource use to that quote.
Exports include the price/supply breakpoints spanning an observed interval.
An interval with a price change or ambiguous publication ordering is marked mixed or uncertain.
Do not apportion its tokens or quota movement between prices in proportion to elapsed time without an explicitly named estimation assumption.

For quota trajectories, begin a new analysis episode on an observed reset/window change, a binding or metric/source compatibility change, a clock reversal, or a gap beyond the proposed fifteen-minute threshold.
An unexplained downward utilization jump creates a boundary/anomaly; it does not establish negative consumption or prove that a reset occurred.
Price changes create exposure boundaries but need not create a new quota episode.
Retain the raw points so different estimators can choose different justified gap and boundary rules later.
Opaque or rolling windows remain typed as such, even if observations within one short episode have a useful trend.

* Storage and failure behavior

Default durable storage is =~/.local/state/llm-usage/<dataset-id>/=, honoring an absolute =XDG_STATE_HOME= override.
Use owner-private directories and files and keep this data outside Git repositories.
Keep operational locks in a configured private local runtime directory; never depend on a lock or a shared SQLite writer on Lustre/NFS.

Write one immutable JSON batch per invocation under =batches/YYYY-MM-DD/<batch-id>.json=.
Construct it in a unique private temporary file on the destination filesystem, flush and fsync, and publish under its unique final name without overwriting an existing batch.
Use an exclusive same-filesystem hard link of the completed file or an equivalent no-replace atomic publication primitive; plain overwrite-capable rename is insufficient.
Record producer identity and content hashes, and sync the containing directory where the filesystem supports the promised durability.
On a filesystem that cannot provide the required atomic publication/durability contract, refuse that storage configuration rather than claiming a durable sample.
Readers process only finalized batches; incomplete temporary files are neither history nor grounds for rewriting another producer's files.

The first reader can scan date-partitioned batches; any later database/index is a rebuildable derived view.
At the example report's compact size of 5,131 bytes, five-minute reporting alone is about 1.48 MB/day, before event/catalog overhead.
Measure actual storage and capture cost in the pilot.
There is no automatic deletion in Slice A; later compaction must preserve identities and correction history.

A successful source fetch is not a committed sample until publication succeeds.
The finalized local receipt makes that batch visible to exports, after all referenced artifacts have been durably published.
An orphan batch without a committed receipt remains outside the visible dataset until an explicit recovery operation validates and accepts it with a new receipt.
On storage failure return a controlled error; a later invocation can record a gap but cannot recreate the lost source reading.
Preserve any valid partial accounting report and independent target failures together.
When collection fails before a report exists, store only an attempt record if storage is still usable.
Exit behavior proposed for =sample=: zero for a committed all-selected-source success, one for a committed partial/skipped/failed attempt, and two for a control or storage failure without a trustworthy committed batch.

Each host/source writes its own producer stream.
The initial central dataset is on one selected owning host; importing immutable batches from another host is explicit, preserves IDs and does not establish a distributed polling lease.
Configure one polling owner per reporting identity, and flag duplicate producers with overlapping scopes rather than summing them.
Automatic cross-host transfer and leader failover are later work.

* Slice B: optional native metadata

Only accept metadata from an explicitly configured source owned by the collecting user.
Filter fields in memory before persistence; never save raw stdin, stdout, stderr, requests, conversation text, tool arguments/results, environment or auth files.
Use dataset-local random mappings for native session/thread identifiers and a private lookup when necessary; do not derive public IDs from tokens or expose native paths.
Preserve existing native configuration and require an explicit adapter installation rather than replacing a user's status line or attaching to a live session implicitly.

** Claude candidate

The [[https://code.claude.com/docs/en/statusline][official status-line interface]] can pass model, quota, estimated cost and duration metadata to an existing-session callback.
Its token fields describe current context/last-response usage, so store them as snapshots, not cumulative token consumption.
The cost counter is a client-side estimate rather than a provider bill; duration measures distinguish session residence from API waiting.
Callbacks may repeat or be absent while idle, and a reset/model change can break counter comparability.
This adapter supplies useful supporting evidence, but complete per-request token accounting needs another verified source.

Wrap or compose a user-selected callback only after checking the installed version and its invocation/cancellation behavior.
Its bounded ingestion should not block rendering on network or storage delays.
Quota readings without independently verified account context remain configured/unverified evidence; they do not silently replace the bound accounting source.

** Codex candidate

The [[https://learn.chatgpt.com/docs/app-server][official App Server interface]] exposes =thread/tokenUsage/updated= and turn lifecycle notifications.
Generated schemas from installed Codex 0.162.1 include thread/turn IDs, =total=/=last= token breakdowns, cache categories and reasoning output.
Capture an allowlisted projection from the owning client's existing stream, with version-specific fixtures for counter behavior, reconnects, model changes and compaction.
The isolated account-quota app-server used by llm-accounting does not observe other sessions' turns; starting another server is not a substitute for that capture path.
The current SuCoder remote-control launcher does not yet provide this telemetry sink.

Do not copy a thread cumulative total into each turn or sum it together with the =last= breakdown.
Preserve token-category inclusion metadata; unavailable billing-category semantics leave monetary conversion unavailable.
A reconnection supplies a new observation baseline, not proof that its entire accumulated counter belongs to the reconnection interval.

** SuCoder context

Add optional allowlisted =launch=, =observed_running=, =observed_exited=, =model_changed= and =decision= records at the existing launch/session boundaries.
A remote launcher can know the selected harness/model/access mapping without collecting native content, but an actual model reroute or mid-session change needs native evidence.
Do not scrape the human =sessions= table or infer that a scheduler allocation/tmux session is active LLM use.
The current replaceable =RemoteSession= record does not preserve historical launches or ordinary per-turn model selection.

Name each exposure measure separately: clock hours, observed session-resident hours, union of open-turn intervals per session, and reported API-wait hours when available.
Concurrent sessions add agent-hours; overlapping turns in one session are unioned before counting that session's open-turn hours.
Tool waits can remain inside open-turn time; this is a workload proxy, not measured inference time.
Missing heartbeats create unknown intervals rather than proving exit or continuous activity.
Costs/counters spanning model changes remain mixed unless the source supports model-specific allocation.

* Estimator-ready exports

** Quota series

Emit one row per genuine source observation, not one copy per consuming route.
Include trajectory key, original report/observation references, captured/source time and bracket, used fraction, reset/duration/window kind, applicability, binding, source version, freshness, coverage, permission/state signals and analysis-boundary flags.
Attach the price/supply publications and breakpoints that overlap the relevant interval, with explicit unknown or mixed exposure.
Include failed/skipped scheduled attempts in a companion coverage stream.

These rows support a signed utilization trend per clock hour within compatible episodes.
They do not establish gross resource consumption, absolute token allowances or per-model contributions to a shared pool.
For opaque windows, depletion pressure remains conditional on an explicitly stated forecast/replenishment assumption.
Provider rounding can conceal small changes; unchanged samples are not a finding of zero consumption.
Keep reported precision and any source-supported resolution bound, without inventing one from decimal formatting alone.

** Usage intervals and hourly reference costs

Emit counter-derived intervals only for compatible, source-verified cumulative flow semantics or explicit interval-flow records.
Two cumulative readings define a quantity over their original observation bracket; do not move it into the most recent five-minute bucket.
An unknown baseline leaves pre-baseline use unallocated; a decrease starts a new counter epoch/anomaly unless a source explicitly identifies a correction.
Missing endpoints, mixed model scopes or unverified semantics remain unavailable for that rate.

Each row carries quantity/category/inclusions, interval, route/account scope, provenance, attribution quality, applicable tariff version and the named hour denominator with its coverage.
Report =provider_rated_cost= and =local_api_equivalent_estimate= as separate series.
Do not sum inclusive cache/input or reasoning/output categories, nor a session total and its components.
When the native source lacks sufficient token detail, a declared hourly prior remains preferable to an invented exact cost.

** Reproducibility and interpretation

Every export records a cutoff, view/method version, source event IDs, binding/catalog versions and boundary/coverage rules.
Separate the requested source-time range from the receiving dataset's knowledge snapshot.
An export freezes a content-addressed input manifest listing the exact accepted receipts and artifact hashes visible to that export; its snapshot ID, rather than a wall-clock timestamp alone, defines reproducible replay.
Resolve the required earlier registry, supply and price publications through that manifest even if they precede the requested time range.
Missing references remain explicit; the reader must not search newer state outside the manifest to fill them.
Replaying the same manifest, source-time range and view/method rules produces the same rows; late imports and corrections require a new snapshot ID.
Recording price vectors and supply state supports future conditional demand models, but does not label price endogeneity, latent unmet demand or quality substitution as solved.
No rate, price or availability estimate authorizes inference or reserves quota.

* Synthetic acceptance cases

The replay fixture contains quotes changing at 12:07 between quota readings at 12:05 and 12:10, native cumulative readings of 1,000 and 1,300 over that interval, a failed 12:15 sample, and a new reset episode at 12:35.
The correct export preserves one 300-token interval with mixed price exposure, does not assign its quantity to either quote, records the failed tick, and does not fit a trend across the reset/gap.
The shared quota readings belong to one constraint each, even though two declared model routes share the allowance.

Before implementation is accepted, synthetic tests must additionally cover:

- Identical batch imports, conflicting payloads under one event ID, local =o001= alias reuse and report re-export without new source collection.
- Partial metrics, zero versus missing values, stale/prior/conflicting readings, provider lag and unchanged rounded percentages.
- Changed namespace/account generations, changed applicability, moved reset timestamps, rolling releases and limit revisions.
- Clock reversal, uncertain cross-host order, late imports and ambiguous price activation boundaries.
- A missing price publication, an unobserved intermediate quote, stale quote use by a decision and a branched publication history.
- An expired Claude credential with no inference/auth mutation, provider Retry-After across restart, throttling without a usable retry timestamp, a busy tick and bounded collector failure.
- An outer cancellation/deadline that reaps independently sessioned native children before another attempt acquires the owner lock; hard-deadline rejection on an unsupported host.
- Crash before publication, disk full, malformed finalized batches, simultaneous producers and an imported duplicate source stream.
- Counter restart/reconnect, repeated callback, model switch, partial native coverage and inclusive token categories.
- Quiet sessions, dead agents with live tmux/Slurm jobs, missing heartbeats and concurrent open-turn intervals.
- An offline export that touches neither credentials nor providers and contains no canary prompt, token, path or raw diagnostic.

* Implementation sequence and checks performed

1. Restore/test passive combined Claude collection and document the accounting policy; this is a small prerequisite in llm-accounting, separate from history storage.
2. Implement batch validation/storage, saved-report ingestion, manual price/supply publication and offline quota export; run the replay before enabling live collection.
3. Add the bounded five-minute sampler, durable cooldowns and a user-timer example; pilot on one owning host with explicitly selected targets.
4. Inspect source lag, quantization, gaps, storage size and capture overhead; record which constraints support useful rate estimates and which remain conditional.
5. Add native/context adapters one at a time after verifying their capture path and semantics, followed by estimator and SuCoder consumption work.

On 2026-10-17, all 270 existing llm-accounting tests passed and its offline validator accepted three schemas and fourteen synthetic examples.
These checks establish the reused baseline; they do not test an unimplemented history collector.
The installed Codex schema was generated offline without launching a session or accessing credentials.
The replay contains seven batches and four accounting reports; all report schemas, account bindings, artifact hashes and publication references validate offline.
Its two counter samples differ by 300 tokens and span the intervening price publication, as expected.
Org lint, ASCII, whitespace and local source-link checks pass.

Independent reviews of data semantics and operations found gaps in late-import replay, quota re-export identity, throttle fallback and native deadline cleanup.
The final design resolves them with mandatory receipts and input manifests, candidate source-fact keys, persisted fallback backoff and cleanup/containment requirements.
Both reviewers rechecked those changes and found no remaining material issue within the design scope.

From the SuCoder mirror root, the replay's existing accounting artifacts can be revalidated without credentials or provider requests:

#+begin_src sh :eval no
../llm-accounting/.venv/bin/python - <<'PY'
from pathlib import Path
import hashlib, json
from llm_accounting import validate, check_binding
fixture = json.loads(Path("docs/examples/llm-usage-collection-v1.json").read_text())
config = json.loads(Path("../llm-accounting/examples/model-limits/config.json").read_text())
for batch in fixture["batches"]:
    for ref, artifact in batch["artifacts"].items():
        report = artifact["value"]
        validate(report, "report")
        check_binding(config, report)
        encoded = json.dumps(report, sort_keys=True, separators=(",", ":"), ensure_ascii=True).encode("ascii")
        assert ref == "sha256:" + hashlib.sha256(encoded).hexdigest()
print("Replay accounting artifacts validate.")
PY
#+end_src

The proposal chooses a five-minute cadence, immutable batches, no automatic deletion, explicit publication history and a passive first slice.
Decisions needed for a live pilot are the owning host/account targets, initial advertised prices, declared supply/rate assumptions and which native adapters, if any, to install.
The design and offline replay do not depend on those account-specific choices.
