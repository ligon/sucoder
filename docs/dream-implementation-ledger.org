* 3. Definitions and conventions

- Source admission :: A strict version-1 JSON request names a configured repository, a full integration ref, and nonempty explicitly shareable-or-private git or native-JSONL units.
- Git passage :: Inclusive one-based lines map to half-open byte offsets in the committed blob; working files and their mtimes are irrelevant.
- Identity :: A repository UUID plus kind and logical path identifies a source; commit, blob, selected range, and SHA-256 identify its revision.
  A provisional UUID is only a proposal until integrated, as specified in the design's source registry contract.
- Coverage :: Planning records selected/chunked bytes, not extraction, comprehension, verification, or accepted progress.
- Plan :: A private, content-addressed manifest; changing any frozen input or limit changes its identity.
  A successful plan does not imply an executable backend or a prepared candidate.
- Backend :: Evidence kind and execution harness are independent.
  A role adapter accepts frozen assignments and returns schema-bound results, delivered ranges, trace evidence, usage and capability limitations.
  The coordinator owns budgets, validation, receipts, and git publication for every backend.
- Transcript :: An explicitly named canonical local regular file, expected native thread identity and complete-line prefix.
  Its digest binds exact bytes; normalization preserves native order, provenance and unknown records, and marks session completion/independence unestablished.
- Semantic candidate :: A fresh topic and navigation entry rendered from cited model-checked claims, under =inline-semantic-roles-v1=.
  It is distinct from quotation fidelity and from integrated progress; unresolved claims retain explicit caveats, and contradicted claims are omitted.
- Attempt :: An explicit independent native run identity with its own allowance.
  A per-run advisory lock prevents duplicate provider work; validated results are reusable, while a started request with no validated result requires a new explicit attempt.

* 4. Invariants

Never fetch, invoke inference, run hooks/filters, call a scheduler, initialize a repository, change its refs/worktree/index, or reinterpret admitted text as instructions during planning.
Reject unsupported kinds/versions, duplicate IDs/JSON fields, path traversal, symlink/gitlink sources, ambiguous binding, missing objects, invalid text/ranges, and predictable budget overflow.
Read only explicit git objects or selected transcript prefixes, with byte and time limits; do not crawl homes or discover transcripts.
Keep plans outside every inspected repository with private directory/file modes without changing the process umask or existing directory permissions.
Freeze prior wiki object identities and mark progress as unevaluated until receipt/output validation exists.
No backend fallback, provider dependency, permission bypass, or claim of source containment follows from a plan.
Native runs require an explicit model and shareable selections, and transmit only the frozen assignments and prior context to the authenticated provider.
Linux Landlock confines the native process tree; unsupported kernels/builds fail before inference.
External model tools, inherited settings/plugins/hooks and parent session/relay context are disabled or excluded; authentication is staged separately in a private temporary home.
The provider connection retains network access; do not describe filesystem confinement as operating-system network isolation.
Only the coordinator renders shared Org and writes receipts/git objects; native success prose cannot establish delivery or semantic truth.
