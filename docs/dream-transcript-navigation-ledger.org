* 3. Definitions and conventions

Session ranges are half-open raw byte offsets, as =read_range= states: =[byte_start, byte_end)=.
Project-file reads instead use inclusive one-based line numbers.
An eligible session is a scoped finished session pinned at its last complete line; filename discovery does not establish arbitrary transcript admission.
=claude-view-v1= is the admitted rendering of a complete-line raw range, with raw and rendered digests; it is not the original raw tool output.
Accepted session consumption comes from published receipt ranges, not navigation or an analyzer's completion claim.
The selected-evidence allowance is six units and 65,536 rendered/UTF-8 bytes; navigation delivery defaults to 131,072 bytes.
Public response bytes use canonical JSON encoding, including escaped text, metadata and cursors.
The inventory metadata counter counts explicit directory/candidate stat checks; canonical path checks and existing Git/historical helpers also remain inside the processing deadline.
Version 3 search completion is explicitly unfrozen; it does not establish query absence in a coherent source revision.
Unknown actual reads remain unknown, with known bytes and frozen upper bounds reported separately.
Native-call limits include discovery finish, authorship, review and repairs; hidden provider HTTP retries are outside that unit.

* 4. Invariants

Earlier job headers, briefs, schemas, assignments and lookup observations must reconstruct unchanged.
The 16 MiB admitted-range guard remains a range bound, never a whole-session eligibility test.
Keep scoped discovery, canonical regular-file access, native identity checks, redaction, complete records and rejection of changed selected bytes.

Appends after the pinned end do not enter an existing job's evidence.
Prefix length and session identity do not establish a frozen content revision across pages.
New resource guarantees must cover CPU, enumeration and metadata work as well as raw I/O and model delivery.
Only admitted and independently reviewed evidence can support publication; scanned and delivered ranges have different meanings.
Closeout reserves and author capacity survive discovery, shared-wallet use and explicit retries.

* 5. Reuse decisions

- Reuse :: Existing range admission, rendering bytes, redaction semantics, attribution map, receipt consumption, role transport, lookup journal and whole-job wallet.
  Reusing rendering semantics does not establish interruptible execution; the deadline boundary remains a design decision.
- Extend :: Session read/search callers and complete-prefix probing with a bounded record iterator; the existing whole-prefix navigation cannot page large sessions.
- New :: A versioned opaque continuation cursor, because a session ordinal cannot resume midway through a session or a multi-block record.
- New :: A killable POSIX processing worker with bounded output and additional address-space headroom; byte guards and the current renderer cannot enforce CPU deadlines.
  A versioned optional =processing= policy travels with new rendered source requests and admitted units; older units keep their execution path and bytes.
- Extend :: The lookup artifact becomes one version 3 envelope containing the observation, raw read receipts and continuation body, so replay preserves deadline stops without reopening mutable navigation sources.
- Extend :: Explicitly unfrozen search completion and raw digest binding for a resumed record; no existing primitive pins an immutable whole-prefix revision without reading it.
- New :: An automatic discovery-allocation policy for new jobs; current defaults cannot distinguish a deliberate eight-call ceiling from an inherited default.
- Extend :: Existing source/response accounting with scanned, skipped and delivered intervals, retaining receipt semantics for accepted coverage.
- Extend :: Frozen advice with a per-attempt/step navigation-allocation record, so live-wallet decisions do not change assignment reconstruction.
- Extend :: The planner's existing inspection deadline through an optional =create_plan= keyword for new jobs, preventing admission from refreshing the shared deadline while preserving earlier defaults.
- Preserve :: The current =claude-view-v1= bytes for the same admitted range; a renderer change would require its own contract migration.
