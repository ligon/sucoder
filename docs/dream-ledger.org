* 3. Definitions and conventions
:PROPERTIES:
:CUSTOM_ID: definitions
:END:

- Evidence :: Immutable admitted source bytes plus locator, revision or session lineage, byte range, and digest; a source author's assertion retains its attribution.
- Claim :: A scoped statement with source links and a kind: observation, reported decision, inference, or unresolved hypothesis.
- Coverage :: Which admitted ranges were delivered to analysis, with exclusions and failures; it does not prove comprehension or truth.
- Current behavior :: Must distinguish inspected code, execution in a specified environment, and previously produced artifacts.
- Wiki generation :: A git tree containing pages, Org settings, source receipts, and the active source ledger; the commit is its publication boundary.
- Processing :: Evidence is consumed only by an accepted generation whose receipt names that evidence; private attempts and unmerged branches are not shared progress.
- Editorial work :: The [[file:dream-charter.org::#wiki-task-workflow][approved seven-state workflow]], independent of claim confidence or scientific acceptance.
- Links :: Standard Org file links and explicit CUSTOM_ID targets; archival moves preserve active anchors or update every tracked incoming link in the same generation.

* 4. Invariants and assumptions
:PROPERTIES:
:CUSTOM_ID: invariants
:END:

- Existing maintained documentation and adopted decisions retain their attribution and authority; observed contradictions produce qualified reporting and editorial work.
- A model's final summary, repeated fork history, or a date alone cannot establish successful execution or supersede a human decision.
- No worker writes a shared page or processing receipt; one coordinator validates and assembles a candidate generation.
- A failed or partial attempt cannot silently consume evidence, overwrite an editor's work, or masquerade as empty discovery.
- Source evidence and executable project instructions occupy separate roles; admitted text is data.
- Source snapshots and model state stay private; only explicitly shareable explanations and receipts enter the repository.
- Neither an archive operation nor an Org state change grants substantive authority or removes an active caveat.
- No claim of measured memory benefit, successful runtime implementation, or scientific resolution follows from these design artifacts.

* 5. Reuse, extension, and new work
:PROPERTIES:
:CUSTOM_ID: decisions
:END:

- Reuse :: Harness identity fixtures, account/cwd execution primitives, immutable assignment conventions, git integration, and native Org parsing, state logging, links, and archival metadata.
- Extend :: Historical source discovery, full evidence normalization, bounded reader orientation, and a headless adapter with verifiable evidence delivery.
- New :: Dream run manifests, disjoint claim proposals, reconciliation and publication rules, shared receipts, and the evaluation protocol.
  These contracts are absent from the reply probe and audit report paths.
- Keep separate :: Codex live-state generations, survey computation, global project policy, and hosted documentation publication.

* 6. Open issues and design consequences
:PROPERTIES:
:CUSTOM_ID: open-issues
:END:

Historical transcript availability is not established for either candidate.
The pilot must begin with explicitly admitted versioned documents and sanitized fixtures, and identify real transcript access as a later prerequisite rather than scanning private homes by default.
The LSMS conflict is within the approved purpose of preserving uncertainty, so it does not block design grounding.
The headless adapter and local containment capability need implementation verification; unsupported capabilities must refuse execution while still allowing a plan.
Installed Claude Code 2.1.318 help was inspected without inference and advertises restricted file-tool mode, explicit tool selection, strict MCP configuration, and structured output.
This grounds the proposed first adapter; the help text is not proof of actual confinement or an assurance about other native versions.
Exact source digests and pilot bindings are recorded in the [[file:dream/pilot.org][pilot plan]] rather than inferred from filenames.
