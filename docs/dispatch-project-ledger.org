* 3. Definitions

A profile is explicit nonsecret configuration plus a frozen bootstrap and
approved input identities. Reader credentials are private files, separate from
native model authentication. Dynamic worker paths are resolved only in the
receiving allocation. A bootstrap receipt configures the later process through
validated JSON; exports from a terminated child shell do not configure it.
Infrastructure completion, worker task claims and scientific acceptance are
separate. Reviewers verify the candidate privately, before a human integrates
the LSMS development PR.

* 4. Invariants

Preserve existing dispatch behavior when no profile is supplied. Profiles may
not overwrite HOME, native homes, scheduler/control/Git identities or increase
CPU budgets. Writable paths and returned PATH prefixes stay on the receiving
node; reject PATH separators/NUL and recognized Python writable-state overrides.
Bootstrap receives no provider secrets by default. Freeze initial helper
bytes and profile choices; copy and verify approved assets before using them.
Wrong assets/imports or setup failure prevent native launch. TERM and setup
failure clean up owned mount/helpers even before a native child exists.
Pending cancellation prevents version inspection and native launch. A verifier
checks HEAD, the actual index and tracked bytes after owned cleanup; source
drift invalidates a zero test exit. Ignored/untracked outputs remain permitted.
Placement ignores permission errors only when fresh kernel metadata proves
the process is a zombie/dead or its PID directory is gone. A live or unknown
process remains an inspection failure, including the second mount-info pass.
Never clear shared L2 caches, repoint the mirror's venv or silently copy its
writable venv master. Preserve missing/unexecuted credentialed checks explicitly.

a portable project-profile preparation helper, because the core intentionally
has no project contract. Its preparation is shared with deterministic jobs.
LSMS bootstrap/profile examples and a verifier adaptation belong at that
boundary, rather than LSMS-specific branches in the generic supervisor.
