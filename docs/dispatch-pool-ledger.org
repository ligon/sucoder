* Ownership and invariants
JobOwnership remains the default for independent jobs. A validated pool binding
selects StepOwnership(job_id, step_id, proc_root, uid, supervisor_pid), matching
numeric step components in every observed Slurm hierarchy and PID incarnation.
All existing cleanup call sites use that owner; no pool action cancels a job.
Each worker uses /local/job<ID>/workers/<dispatch-id> for managed state, SQLite,
checkout, data, caches and temporary files. Shared immutable image bytes may be
read from an explicitly pinned allocation asset cache; mounts remain private.

* Reuse plan
Reuse dispatch.submit staging and durable results.git publication. An internal
execution binding changes only scheduling to srun in an already owned allocation.
Pool attach validates scheduler uid, node, capacity and end time. Atomic mkdir
locking serializes conservative CPU/memory reservations; unknown submissions
retain budget until exact step terminal proof. No age-based lock stealing.
Reuse project profiles without new generic scientific or credential policy.
